# Every file-system call, session-file name and shell command that writes, in the shipped code of designos-app, that does not go through
# the routed helpers of `agent_session_files`, with the reason it is safe. Read by `fs_sites_scan_tests` (its header says what is a line
# and what is a whole file).
#
#   FILE<TAB>file<TAB>reason                      a file that never receives a path in a session folder: its file-system calls are exempt
#   LINE<TAB>file<TAB>count<TAB>text<TAB>reason   a line, by file and trimmed text, and how often it occurs there
#
# A hook command is a command the agent's CLI runs as the user, with the session folder as its working folder. It writes through a link
# the agent left there, so no hook writes or reads a file in the session folder: every file of a hook lies in the hook folder of the
# session (`<data dir>/designos/ap/<sid>/hook-out`, `agent_hook_outputs`), which no agent write grant reaches. The one session file a
# hook touches is the patch log, and only measured with `stat`. A row about a hook command says which file of the hook folder it uses.
