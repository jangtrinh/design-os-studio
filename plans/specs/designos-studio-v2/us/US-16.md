## 1. User Story
As a **Principal Systems Engineer, Product Designer and AI Architect**, I want the **`design`:os studio** graphics and scene-graph core (`designos-doc`, `designos-fig`, `designos-render`, `designos-gpu`, `designos-app`) to perform 1:1 on par with the Figma Desktop C++/WASM engine (`fullscreen/lib/scenegraph/FGBoundsAndRenderingInvalidator.cpp`, `fullscreen/lib/shared-app/interactions/FGHitTesting.cpp`, `fullscreen/lib/render-tree/RTCompositeTileCache.cpp`) on real design files with more than 1 million nodes (`/Users/jangtrinh/Downloads/VSF - PCP.fig`: `155,297` raw nodes expanding to **`1,082,535` node instances** across `26` pages, with the `V-Builder` page alone holding `159,644` nodes) — loading the whole file in **`6.25s`** (down from `58.9s`), single select / 30k-node container select / 200-node marquee select in **`0.06ms–0.22ms`**, `hit_test_with_index` in **`0.08ms`**, `comp_ops::with_sync` sync in **`0.001ms`** and `layout_node` recompute in **`2.65ms`** — so that every select, drag, zoom and direct edit on the Canvas stays locked at 120fps without stutter.

## 2. Flow
- Entry condition: The user opens `/Users/jangtrinh/Downloads/VSF - PCP.fig` (`63MB`, `155,297` raw nodes, `165,671` `symbolOverrides`, expanding to `1,082,535` total in-memory nodes) in **`design`:os studio** and goes to the largest page (`V-Builder`, `159,644` nodes).
- Main flow: 1. While loading the `.fig` (`designos_fig::import_fig`), the system decompresses the Kiwi v106 stream and expands the `Instance` tree using an allocation-free `IdHasher` hash map and O(1) `parent_map` / `component_instances` reverse indexes in `Document`, finishing all `1,082,535` nodes in **`6.25s`**, scanning fonts (`app.fonts.load_for`) only on `Text` nodes in **`0.25ms`** and syncing the depth-limited PTY context (`sync_live_file_context`) in **`0.025ms`**. 2. When building the first frame on the `V-Builder` page, `designos_render::SceneIndex` builds a hierarchical spatial index combining a `top_grid` top-level cell grid (`GRID_CELL = 2048.0px`) and a pre-filtered `chrome_nodes` list; every `hit_test_with_index`, `marquee_select_with_index` and `label_rects` query only walks the branches intersecting the viewport/cursor in **`0.08ms–0.22ms`**. 3. When the user drags or edits a node or a group of 200 nodes, `SceneIndex::update_subtree` and `translate_descendants` only update the AABBs of the dirty branch (`dirty_id`), `comp_ops::with_sync` looks up the dependent `Instance`s directly via the O(1) index in **`0.001ms`**, and `layout::layout_node` only repositions the affected container in **`2.65ms`**.

## 5. Edge cases
- Selecting a Section or Frame with more than 30,000 children (`big_container`): `fast_world_aabb` reads the stored AABB directly from `SceneIndex::bounds_of` and `selection_colors_with_counts` caps its sample at `512` nodes so the UI thread never freezes.
- Deeply nested `Instance` trees with hundreds of thousands of `symbolOverrides`: The component dependency index in `Document` completely avoids a linear scan of the `1,082,535` nodes when a leaf node that is not a master `Component` is edited (`with_sync = 0.001ms`).
- Moving a node group during continuous drag at 120fps: `SceneIndex::translate_descendants` translates the child branch's `world_ts` world matrices and `bounds` directly without recomputing path/stroke geometry.
