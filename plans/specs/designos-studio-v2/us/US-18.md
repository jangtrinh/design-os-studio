## 1. User Story
As a **Product Designer, Design Systems Engineer and Prototyping Architect**, I want **`design`:os studio** to fully deliver **Wave 3 of Feature Depth and Micro-Interactions 1:1 with Figma Desktop (`126.9.13`)**, based on `REA` reverse-engineering evidence (`FGCornerRotationBehavior.cpp`, `FGGridTrackBehavior.cpp`, `FGMultiEditHelpers.cpp`, `FGDropperManager.cpp`, `FGParameterDataEvaluator.cpp`) and the `es:micro-interactions` standard — including: (1) **On-Canvas Direct Manipulation Handles** for independent corner radius (`Alt`-drag corner widget), pink `#FF24BD` `Padding` / `Gap` drag bars with Auto-Layout child reordering, 2D CSS Grid column/row track drag lines (`fr`/`px`/`auto`), on-node Gradient stop drag bars and an `11×11` pixel Eyedropper loupe (`I`); (2) **simultaneous Multi-Variant Editing (`Multi-Edit` · `Q` key)** on `ComponentSet`s / `Variants`; and (3) **Variable Expressions & Conditional Prototyping (`SetVariable`, `Conditional` `if/else`, a visual `Spring Physics` velocity curve editor)** — so that even the finest design operations happen directly on the Canvas within a `< 1.0ms` frame budget at 120fps.

## 2. Flow
- Entry condition: The user has a design project open on the Canvas (`S01`) in **`design`:os studio** with Auto-Layout / 2D CSS Grid Frames, a multi-variant `ComponentSet`, or a Prototyping flow (`Design | Prototype | </>`).
- Main flow: 1. **On-Canvas Direct Manipulation Handles (`< 1.0ms` frame budget)**: When the user hovers or selects a node at `zoom >= 0.5`, the system shows direct manipulation handles with an `idle -> hovered -> pressed -> dragging -> committed/cancelled` state machine: drag the inner corner dot to adjust `corner_radius` on all corners (or hold `Alt` to adjust 1 corner alone with an `R: 12px` pill), drag the pink `#FF24BD` strut on an Auto-Layout Frame to adjust `padding` / `item_spacing` (or hold `Alt` to adjust both sides symmetrically), drag the column/row dividers on a 2D CSS Grid Frame to resize `px`/`fr`, drag the Gradient axis and colour stops directly on the node surface, or press `I` to open the `11×11` pixel Eyedropper loupe to sample colour precisely per pixel. 2. **Multi-Edit Across Variants (`Q`)**: When a node inside one variant of a `ComponentSet` is selected and the user presses `Q` (or the `Multi-edit variants` button on the contextual toolbar), the system uses `FGMultiEditHelpers` / `comp_ops` to automatically select all corresponding nodes (`matching sublayer path`) across every variant in the `ComponentSet` and instantly syncs every resize, colour change, text edit or alignment in 1 `History` step (`Cmd+Z`). 3. **Variable Expressions & Conditional Prototyping**: In `Prototype` mode and the `Variables` dialog, the user configures `SetVariable` actions with numeric/string/boolean expressions (`count + 1`, `!isOpen`, `price * quantity`) and `Conditional` (`if / else`) branch blocks with a spring physics curve (`Spring Physics`: `stiffness`, `damping`, `mass` with a live oscillation graph); when running `Present`, the `prototype_expr` executor evaluates the expressions and updates variable-bound nodes in real time.

## 5. Edge cases
- Cancelling a drag midway with `Escape` or losing window focus (`Blur`): The micro-interaction state machine moves immediately from `dragging` to `cancelled`, restores the pre-drag `Node` snapshot and pushes no extra command onto the `Undo` stack.
- A variant in the `ComponentSet` is missing the corresponding node when `Multi-Edit` (`Q`) is on: The system only selects variants whose child branch matches the path, shows a `"Multi-editing N/M variants"` badge and safely skips variants without that node.
- A `SetVariable` / `Conditional` variable expression divides by `0` or references a deleted variable: `prototype_expr` returns a safe fallback value (`NaN`-guard / `false`) without panicking the `Present` session.
