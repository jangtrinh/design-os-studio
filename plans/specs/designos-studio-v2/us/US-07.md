## 1. User Story
As a **Systems & Format Reverse Engineer**, I want to analyse the `/Applications/Figma.app` bundle (`app.asar`) and real `.fig` files (`VSF - PCP.fig`, Kiwi v106) with the `morluto/rea` toolkit, so that I can extract the full Kiwi schema definitions (653 definitions), the `NodeChange` field mapping, the `symbolOverrides` override mechanism and the UI3 colour/size tokens needed to build the 1:1 Rust core.

## 2. Flow
- Entry condition: The `/Applications/Figma.app/Contents/Resources/app.asar` bundle and the sample document `/Users/jangtrinh/Downloads/VSF - PCP.fig` are available on the workstation.
- Main flow: 1. Run `rea analyze-javascript-application` and `rea inspect-artifact` on `app.asar` and `canvas.fig`. 2. Unpack and decode the Kiwi v106 Schema chunk and the 155,297 `NodeChange` records. 3. Export the technical report to `plans/specs/designos-studio-v2/research/` and map it directly to the `crates/designos-fig/` decoder/encoder.

## 5. Edge cases
- Empty (`empty`): When an `images/<sha1>` image chunk in the `.fig` package has not been downloaded locally, keep the image hash reference and draw a `checkerboard placeholder` without breaking file loading.
- Error (`error`): When encountering a new enum definition or Kiwi field from a future Figma version (> v106), store it safely in `raw_fields` instead of refusing to open the file.
- Large content (`loading`): Smoothly handle `.fig` files with over 150,000 `NodeChange` records and remove orphan nodes via `Document::prune_unreachable`.
