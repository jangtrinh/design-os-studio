## 1. User Story
As a **Product Designer, Systems Engineer and AI Operator**, I want **`design`:os studio** to integrate the **Dual-Layer Auto-Update (`S09`)** mechanism and the **Cross-Platform Release Packaging Workflow (`macOS`, `Windows`, `Linux` · `DIR-22`)**, consisting of (1) an atomic auto-updater for the app/CLI (`updater.rs` + `designos update`) supporting the 3 channels `Stable | Beta | Nightly`, `SHA-256` verification and automatic rollback from `.bak`, (2) complete user installers on macOS (`.app` + `.dmg`), Windows (`-setup.exe` + `install.ps1`) and Linux (`.deb` + `install.sh`) that automatically output `dist/release-manifest.json` + `SHA256SUMS`, and (3) a passive `Watchdog` that detects when `/Applications/Figma.app` (`app.asar` & the `.fig` Kiwi schema) upgrades so it can sync instantly, keeping installs safe and maintaining 99% 1:1 compatibility with Figma.

## 2. Flow
- Entry condition: The user installs **`design`:os studio** from an installer (`macOS .dmg/.app`, `Windows -setup.exe/install.ps1`, `Linux .deb/install.sh`), launches the app (`S04`/`S01`), opens the `Desktop app > Check for Updates…` menu (`S09`), or runs the CLI command `designos update`.
- Main flow: 1. **Layer 1 (Self-Updater)** moves from `Idle` → `Checking` → `UpToDate` or `UpdateAvailable(ReleaseManifest)` on the chosen channel (`Stable`, `Beta`, `Nightly`). 2. Download the update package in the background (`Downloading(pct)`) into `current_exe.staged`, check the hash in `VerifyingSha256`, back up the current build to `current_exe.bak` and move to `StagedReadyToRestart` → `Applied` (or automatically restore with `RolledBack` on failure). 3. **Layer 2 (Figma Schema Watchdog)** checks `/Applications/Figma.app/Contents/Info.plist` read-only (`CFBundleShortVersionString`, e.g. `126.9.13`) and the modification time of `Resources/app.asar` along with the Kiwi schema version (`v106`), showing a `Sync Figma Schema` notice when it detects a change.

## 4. Acceptance Criteria

| ID | Given | When | Then | Scenario |
|---|---|---|---|---|
| AC-01 | The user configures the `Stable`, `Beta` or `Nightly` channel (via the `S09` UI, the `Check for Updates…` menu, the `designos update --check` command or the `DESIGNOS_UPDATE_CHANNEL` variable) | The system checks for a new release (`ReleaseManifest`) | The state machine moves correctly from `Idle → Checking → UpToDate` or `UpdateAvailable`, showing a non-blocking update badge on the Home sidebar `S04` and the Top Bar `S01` along with the `Release notes`. | SCN-09-01 |
| AC-02 | A new update package is being downloaded and prepared to apply (`Downloading → VerifyingSha256`) | The `SHA-256` hash matches (or mismatches due to a network error/corrupt file) | When `SHA-256` matches, the new file is written to `.staged`, the old build is saved to `.bak` and atomically swapped into `StagedReadyToRestart`; when `SHA-256` mismatches or startup fails, the system refuses to overwrite and automatically restores from `.bak` (`RolledBack`). | SCN-09-02 |
| AC-03 | The `/Applications/Figma.app` install on the macOS machine is upgraded to a new version or `app.asar` / the `.fig` Kiwi schema (`v106`) changes | `FigmaSchemaWatchdog` passively scans `Info.plist` and `app.asar` read-only | The system detects the new Figma version without opening a Figma window, shows a sync warning in `S09` and allows running `Sync Figma Schema` in 1 click or via the CLI `designos update --sync-figma-schema`. | SCN-09-03 |

## 5. Edge cases
- Empty / Offline (`empty`): When the workstation has no network connection or `/Applications/Figma.app` is not installed, keep the `Offline / Local Schema v106 Active` state without showing annoying error popups.
- Verification error (`error`): When the `SHA-256` hash of the `.staged` file does not match the `ReleaseManifest`, delete the `.staged` file immediately, keep the current executable and log a security warning.
- Downloading / Write permission (`disabled`): Disable the `Restart to Apply` button while the state is `Downloading(pct)` or `VerifyingSha256`; enable the `Rollback to previous version` button only when a `.bak` file exists on disk.
