## 1. Context and Problem Statement

AI-native product design and development teams are fragmented across 3 separate tool surfaces:
1. **Figma Desktop (`com.figma.Desktop` UI3 `126.9.13`)** for designing vector UI across multiple project tabs open in parallel, managing Components/Variables and storing the binary `.fig` format (Kiwi container v106).
2. **Spec Driven Reader (`product-os-spec-driven`)** for managing Format v2 spec packages (`Intake`, `Clarify`, `Contract`, `PRD`, `US`, `Wireframe`, `Prototype`, `Design`, `TDD`, `UIUX`, `Handoff`), the 12-column `ui-contract.md` matrix and the review Gates `G1..G5`.
3. **CLI Agent Terminal (`claude` / `codex` / `agy` / `grok` / `$SHELL`)** for running AI coding agents, generating `.spec.json` UI and running automated tests.

**`design`:os studio** (always all lowercase, with **`design`** in bold and `:os studio` in lowercase) unifies all 3 surfaces in a single 120fps native Rust/egui/wgpu app, reaching **99%+ 1:1 parity** with Figma Desktop UI3 on the v106 `.fig` binary format, the **Multiple Tab Project Strip (`36px`)**, the **`Agents` Left Side Panel (`S13`)**, the **unified Phosphor Icons system (`https://phosphoricons.com/`, `DIR-19`)**, the **5-Pillar Quantitative Parity Meter (`S12`)** and the **Dual-Layer Auto-Update Architecture**.

## 3. Project Classification and Architecture Constraints (Classification & Constraints)

- **Pipeline classification (`pipeline.yaml`)**: A complex project (`Complex`), activating all **11 stages** of `product-os-spec-driven` Format v2 (`intake` → `clarify` → `contract` → `prd` → `us` → `wireframe` → `prototype` → `design` → `tdd` → `uiux` → `handoff`) and the **5 review Gates (`G1..G5`)**.
- **Mandatory technical constraints**:
  1. No dependency on Electron or a web browser for the rendering core; the whole Canvas, UI3 Chrome, Multi-Tab Project Workspace, `Agents` Left Side Panel, Unified Phosphor Icons (`resvg`), Spec Reader v2, PTY Terminal and Auto-Updater run in pure Rust (`designos-doc`, `designos-fig`, `designos-render`, `designos-gpu`, `designos-export`, `designos-app`, `designos-mcp`).
  2. Every automated UI verification screenshot command (`--screenshot`), `--parity-report` report and update/watchdog check must run in the background (`with_active(false)`), never showing a window over the user's working screen.
