# Report: SwiftUI String Escape (`#1003` RT-03) and `designos-diff --version` (`#1088`)

## 1. What could NOT be verified

- **FACT:** `designos-app` test binaries were not built or executed (prohibited by the task harness constraint: *"Disk is tight: do not build `designos-app`'s test binaries"*). `designos-app` was checked via `cargo clippy --workspace --all-targets --locked -- -D warnings` (exit `0`).
- **FACT:** Linux and Windows builds/tests were not executed locally (macOS host `arm64-apple-macosx26.0` only).
- **FACT:** In `SwiftUI`, `Text("...")` calls `Text.init(_ key: LocalizedStringKey, ...)` by default when no explicit `verbatim:` label is used; while any valid Swift string literal (`"cost ${y}"`, `"\\(x)"`) now parses and type-checks cleanly under `swiftc -parse` and `swiftc -typecheck`, runtime `LocalizedStringKey` Markdown interpretation inside Apple's SwiftUI framework on device was not changed or tested because the generator emits `Text("...")` by design across all existing SwiftUI goldens.

**Conclusion:**
- **FACT:** Draft PR https://github.com/jangtrinh/design-os-studio/pull/1090 opened against `release/v0.6.2` (`Closes #1088`, mentions RT-03 of `#1003` without closing `#1003`).
- **FACT:** RT-03 of `#1003` is fixed in commit `3073f0e47`: `crates/designos-export/src/swiftui.rs` now uses `swift_quote` (from `crates/designos-export/src/codegen.rs:541`) instead of Kotlin-oriented `quote` (which escaped `$` as `\$`) and raw format interpolation, so `${y}`, `\(x)`, quotes, backslashes, newlines, tabs, carriage returns, control characters (`\u{...}`), and emoji are emitted as valid Swift string literals. Both `swiftc -parse` and `swiftc -typecheck` (Apple Swift 6.2.3) ran and exited `0`.
- **FACT:** `#1088` (QA V-03) is fixed in commit `e781903d9`: `crates/designos-diff/src/main.rs` adds `version` to `#[command(name = "designos-diff", version, about = "Pixel diff harness")]`, so `designos-diff --version` and `designos-diff -V` print `designos-diff 0.6.1` and exit `0`.

**Weakest link:** `swiftc -parse` inside `swiftui::tests` is conditional on `swiftc` being present on `PATH`, so on CI runners without `swiftc` only the Rust string assertions run.
