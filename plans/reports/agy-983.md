## 3. Root cause (`file:line`)

- **`crates/designos-doc/src/components.rs:1129-1131`** (inside `apply_reference`, called from `sync_pair` at `crates/designos-doc/src/components.rs:1337`):
  When a main component is edited, `sync_instances` (`crates/designos-doc/src/components.rs:792`) -> `sync_component` (`:798`) -> `sync_one` (`:846`) -> `sync_pair` (`:1292`) -> `apply_reference(&rn, &mut n, top, &values)` (`:1337`) iterates over `ALL_FIELDS` (`crates/designos-doc/src/components.rs:20-37`, where `OverrideField::Name` is the first entry).
- At `crates/designos-doc/src/components.rs:1129`, `apply_reference` skipped `OverrideField::Transform | OverrideField::Visible | OverrideField::Locked` on `top` instances, but did **not** skip `OverrideField::Name` on instances.
- Because an instance's own layer name is not marked with `OverrideField::Name` in `n.component.overrides` unless explicitly diff-recorded via `record_override` — both when created via `create_instance` (`crates/designos-doc/src/components.rs:648-664`, which names an instance of a variant after its `ComponentSet` and clears `overrides`) and when imported from `.fig` (`crates/designos-fig/src/rest_import.rs:835-1021`, where an `INSTANCE` node's layer name such as `"Contact page header"` is stored directly on the `INSTANCE` record rather than in `symbolOverrides`) — `apply_reference` called `copy_field(OverrideField::Name, r, n)` (`crates/designos-doc/src/components.rs:982`) and overwrote the instance's `n.name` with `r.name` (the main `Component`'s name, e.g. `"Breakpoint=Desktop, Type=Simple"`).
- Similarly, for nested instances inside an outer instance (`top == false`), if the nested instance was swapped to a variant (`crates/designos-doc/src/components.rs:1326-1331`), `rn` is replaced with the variant `Component` node (`root`), so `apply_reference` would also overwrite the nested instance's layer name unless `OverrideField::Name` is skipped for `NodeKind::Instance`.

## 4. Changes per file

- **`crates/designos-doc/src/components.rs`**:
  - In `apply_reference` (`lines 1129-1134`): added `OverrideField::Name` to the `top` skip guard and skipped `OverrideField::Name` whenever `matches!(n.kind, NodeKind::Instance { .. })`, so syncing a main component never overwrites any instance's layer name while preserving all other synced fields and non-instance child layer name syncing.
  - In `mod tests` (`lines 3830-4001`): added `DeferredPageTestHydrator`, `instance_name_sync_fixture`, `sync_main_text_edit_keeps_instance_layer_names_across_same_loaded_and_unloaded_pages`, and `sync_main_text_edit_preserves_instance_layer_names_across_designos_round_trip`.

## 5. Answers to the two open questions (with evidence)

1. **Are instances on loaded pages renamed too?**
   - **Yes.** `sync_component` (`crates/designos-doc/src/components.rs:798-818`) collects every instance across the entire document via `instances_of_any(c.s, &comps)` (`crates/designos-doc/src/components.rs:367-377`), which scans `doc.nodes.values()` regardless of page or hydration state. Every instance whose `n.component.overrides` did not contain `OverrideField::Name` had its `n.name` overwritten by `r.name` in `apply_reference` (`crates/designos-doc/src/components.rs:1129-1149`).
   - **Evidence:** In `plans/reports/agy-983-evidence/red.log`, `sync_main_text_edit_keeps_instance_layer_names_across_same_loaded_and_unloaded_pages` failed on `dc23fdd4` with all three instances renamed to the variant name:
     `left: [("same page", "Breakpoint=Desktop, Type=Simple"), ("other loaded page", "Breakpoint=Desktop, Type=Simple"), ("unloaded page", "Breakpoint=Desktop, Type=Simple")]`.
2. **Does the wrong name reach a saved file (`.designos` round trip)?**
   - **Yes (before the fix).** `sync_instances` mutates `Node::name` directly in `doc.nodes` via `Command::Update`. Saving a `.designos` file (`Document::to_json` / `Document::to_json_counted` in `crates/designos-doc/src/lib.rs:1325-1401`, called by `crates/designos-app/src/io.rs:395-399`) serializes `self.nodes` directly, where `Node::name` is unconditionally written to JSON and restored by `Document::from_json` (`crates/designos-doc/src/lib.rs:1450-1476`).
   - **Evidence:** In `plans/reports/agy-983-evidence/red.log`, `sync_main_text_edit_preserves_instance_layer_names_across_designos_round_trip` failed on `dc23fdd4` after `doc.to_json()` -> `Document::from_json()` with `left: [("same page", "Breakpoint=Desktop, Type=Simple"), ("other loaded page", "Breakpoint=Desktop, Type=Simple"), ("unloaded page", "Breakpoint=Desktop, Type=Simple")]`, and passes in `plans/reports/agy-983-evidence/green.log`.

  - `crates/designos-app/src/showcase/mod.rs:588-593` (comment: `"Mark OverrideField::Name so a later sync_instances on the master component does not overwrite the instance's custom label with the master component's name"`).

  - `crates/designos-app/src/demo.rs:313` (`n.component.overrides.insert(OverrideField::Name)`).
  Those files were not modified.

## 7. Assumptions

- Non-instance child layers inside an instance (such as `Frame`, `Text`, or shape layers mirroring children of a main component) should continue to sync their layer names from the main component when `OverrideField::Name` is not overridden on that child layer; only `Instance` nodes (`top` or nested `NodeKind::Instance`) keep their own layer name during main-component sync.
