Tool contract:
- `designos_docs_list {project?}` -> `project {id, name(fenced)}`, `has_manifest`, `manifest_hash`, `groups[5] {id, pages[] {path, title(fenced), blocks, front_matter_problems, hash | error}}`, `pins[] {id, file_id, node_id, name(fenced), group, parent_screen}`. A project with no manifest returns five empty groups and creates nothing. One unreadable page gets an `error` entry; it does not fail the listing.
- `designos_docs_read {page, project?, range? {start?, end?}}` -> `page_hash`, `title`/`description` (fenced), `group`, `front_matter_problems[] {field, problem(fenced), fix}`, `total_blocks`, `range {start, end}`, `next_start`, `blocks[] {index, kind, hash, markdown(fenced)}`.
  - Block id = index. `hash` is `Block::hash()`, the value a later per-block write checks. `page_hash` is the whole-file hash.
  - A comment-only `<!-- -->` block comes back as `kind: "raw"`, not hidden.
  - `range` is half-open `[start, end)`; `end` past the page is clamped; a start outside the page, or `end <= start`, is `VALUE_OUT_OF_RANGE` naming the block count.
  - Output is capped at 100,000 characters of Markdown, cut at a block boundary with `next_start` to continue; one block over the cap is cut and flagged `truncated: true`.
  - Errors, all with a fix in the message: unknown project (`INVALID_ARGUMENTS`, ids in `valid_options`); unknown page (`INVALID_ARGUMENTS`, pages in `valid_options`); bad path; page over 8 MiB (`FILE_TOO_LARGE`, fatal, "fix: split the page"); non-UTF-8 / invalid manifest (`DOCUMENT_INVALID`).
- Fence: ids, paths, kinds, hashes, counts and `fix` texts stay plain. Fenced: project name, pin name, page title/description, block Markdown, and the front-matter `problem` text (it echoes the bad value). Page paths stay plain because the agent must pass them back as arguments; they are validated (relative, no `..`, no control characters, <= 512 bytes).
