### 2b. Help-button row-mates
Mechanism: the row check intersects the bounds of every covered widget in the row, `min_dh = max(e.min_dh.unwrap_or(0))`, `max_dh = min(e.max_dh.unwrap_or(0))` (`layout_snapshot.rs:988-1003`). A mate under only the region-wide dy -8 entry contributes [0, 0], the help button's row dh is +2, so the intersection is empty. A mate with no covering entry would contribute nothing, but the region-wide entry covers every widget in the case, so an entry per mate is the only way to raise its bound. Narrowed in this round: mates now `min_dh = max_dh = 2` (exactly the row's measured +2) instead of 2..4, and their reason names the mechanism. The widgets themselves did not move (widget-level dh is 0, so no tolerance applies to them except an exact +2 growth). Help-button entry keeps 2..4 (its own dh is 4, the row's 2). Cannot be narrower: the gate cannot scope a row bound to "help-button only".
