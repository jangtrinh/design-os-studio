# 0.7.0 smoke evidence (controller run, for QA's verdict)

**Build:** Release dry run [40631906398](https://github.com/jangtrinh/design-os-studio/actions/runs/40631906398) on PR #1283 head `bcb69780` (release/v0.7.0 `0fea8c81` plus the release notes and the version bump). Artifact `designos-0.0.0-dev.bcb6978-macos.dmg`, sha256 checked against the artifact's `.sha256`. All four binaries print 0.7.0 (`01-versions.txt`).

**Isolation:** every run used `env -i HOME=<scratch>/home TMPDIR=<scratch>/tmp PATH=/usr/bin:/bin`. No agent CLI ran against the real home. Agent tabs probed versions only, under the isolated HOME (hence "Not signed in" / "Sign-in unknown" in 08a/08b).

**Documents:**
- The Untitled UI kit through an APFS clone (`cp -c`; proof in `00-kit-apfs-clone.txt`). The original is unchanged. The clone's sha256 and mtime are unchanged after every window run (`10-fill-d9-no-hang.txt`).
- Copies of the shipped starter (`crates/designos-app/assets/starter/designos-studio-starter.designos` at release/v0.7.0).
- No client file. No `--fixture`.

**Windows:** one at a time, each started only after Jang had been idle at least 300 s (`gui-runs.txt` records the idle time, exit code and seconds of each run). A 120 s watchdog was armed; no run needed it.

**Jang's ruling (2026-10-28, via AskUserQuestion):** the same rule as 0.6.5. Click-only checks are covered by their tests; everything else is checked on a kit copy with `--screenshot` presets and `designos-mcp`.

## Found while testing (not 0.7.0 regressions)
- **`designos-mcp` saves drop ACLs:** `designos_save_file` with `overwrite: true` drops the file's ACL. The same happens in 0.6.5.
- **`designos-mcp` renders kit instances without their content:** `designos_render_png` of the kit's `Shadows` row (id 20893) draws the main component's `shadow-xs` label, but the six instances come out as blank cards. The app draws all seven labels (`06b-kit-shadow-row-in-app.png`). The same happens in 0.6.5.
