# Issue 1691: grid overlay reads the solver's tracks

Branch: `fix/1691-grid-overlay-row-gap` (worktree `.claude/worktrees/agent-a28f5e83ebb76ac18`). Commit: see `git log` (one fix commit, one evidence/report commit).

## What changed
- `crates/designos-app/src/canvas/grids.rs`: `compute_css_grid_overlay` no longer copies the row gap, column width or row height rules. It takes `grid_row_gap`, `grid_column_widths` and `grid_row_heights` from `designos_doc::layout_solver`. New parameter `own: SizeLimits` (node min/max) so the solver clamps the frame the same way; `node_css_grid_overlay` passes `SizeLimits::from(&n.layout_child)`. Empty grids still show two placeholder rows. Callers in `canvas/draw.rs` (test helper) updated.
- `crates/designos-export/tests/grid_rules_single_source.rs`: source scan now walks `designos-export/src` and `designos-app/src` recursively (from PR 1729).

## PR 1729 evaluation
Sound but narrow: swapping only the row-gap line is behaviour-identical to main (the solver's `grid_row_gap` equals the old inline rule), so no behavioural red test exists for that line alone. Reused: the `grid_row_gap` call and the recursive source-scan test (credited via trailer). Fixed/added: the overlay also duplicated column widths and row heights, and those really disagreed with the solver (below). Renamed the scan tests (`..._export_or_app_sources`) and the module doc.

## Risks
- Overlay now also depends on node `layout_child` limits; any caller building an overlay outside `node_css_grid_overlay` must pass the right `SizeLimits`.
- Column/row x/y positions are still accumulated in the overlay from the solver's widths/heights plus gaps (same formula as `compute_grid`); a solver offset change (e.g. alignment) would need `compute_grid` exposure. Not in scope.
- Column-gap stripe still spans the full frame height (pre-existing behaviour, visible in both PNGs).
