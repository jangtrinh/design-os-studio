## 1. Summary and user story

As the team, we want the cheapest and most trusted signal first: numbers computed from the document and the reference renderer, identical on every machine, that tell us whether an agent's output renders, uses tokens and components, and is free of layout, contrast and spacing defects.

## 3. Behaviour rules

Each metric is computed on the **output scope**: the union of the run's output frames (E15-25 §3.7) and their descendants, excluding hidden nodes. `N` = number of non-page nodes in scope.

1. **`render_success`** ∈ {0, 1} per output frame, averaged over frames: 1 when `render_node(frame, 1.0)` returns a pixmap with non-zero size and the render did not panic (caught with `catch_unwind`), and the frame has at least one visible descendant. A run with no output frame scores 0.
2. **`token_coverage`** = bound bindable properties / bindable properties. Bindable properties per node:
   - each visible solid fill paint (`fills/<i>`), each visible solid stroke paint (`strokes/<i>`);
   - corner radii when non-zero (per-corner keys, grouped as one when all four are equal and unbound);
   - auto-layout `itemSpacing`, `counterAxisSpacing` (when wrapping), and the four paddings when non-zero;
   - text `fontSize`, `fontFamily`, `fontWeight`, `lineHeight` (pixel line heights only);
   - each effect when the node has effects.
   A property counts as bound when it has a variable binding, or when the node takes it from a shared style that is itself bound or is a style (`style_refs` for fill, text, effect). Instances inside scope count through their own overrides only (inherited component values are counted once, on the main component, when the main is in scope). `token_coverage` is `null` when the denominator is 0.
3. **`instance_ratio`** = nodes that are instance roots or descendants of an instance / `N`. Main components count as non-instance nodes.
4. **`lint_per_100`** (map) = `100 × count(rule) / N` for every rule id with at least one finding, plus `lint_per_100.total`. Findings come from running the E15-9 linter (with E15-10, E15-11 and E15-21 rules) on the output scope with auto-fix **off** (E15-13 disabled), so metrics measure what the agent wrote.
5. **`contrast_failures`** = count of findings of the contrast rule family (E15-10).
6. **`clipped_text`** = count of text nodes with a clipped-text or overflowing-text finding (E15-9).
7. **`off_grid_pct`** = `100 × off-grid values / checked values`, from E15-11's grid rule: checked values are x, y, width, height of every node not positioned by auto layout, plus every gap and padding; a value is off grid when `|v − 4·round(v/4)| > 0.01`.
8. **`auto_layout_coverage`** = frames (and components) in scope with ≥ 2 visible children that use auto layout or grid / all such frames. `null` when there are none.
9. **Rule map.** `rule_map.toml` maps each metric to registry rule ids:
   ```toml
   [contrast_failures]
   rules = ["<E15-10 rule id>"]
   [clipped_text]
   rules = ["<E15-9 clipped id>", "<E15-9 overflow id>"]
   [off_grid_pct]
   rules = ["<E15-11 grid id>"]
   ```
   The concrete ids are filled from the E15-9 registry when this task is built. A test asserts every id in the map exists in the registry, and that every registry rule in the families `contrast`, `text-clip`, `grid` is mapped, so renames fail CI instead of silently zeroing a metric.
10. **Agreement with the linter (AC2).** `contrast_failures`, `clipped_text` and every `lint_per_100` count are taken from the linter's own result on the same document, never recomputed. A test runs the linter directly and compares counts.
11. **Determinism.** Metrics iterate nodes in `NodeId` order and use only the document and the CPU render; floating values are rounded to 6 decimals in JSONL.

## 4. Data model / schema

```rust
pub struct DeterministicMetrics {
    pub render_success: f64,
    pub token_coverage: Option<f64>,
    pub instance_ratio: f64,
    pub lint_per_100: BTreeMap<String, f64>,   // rule id -> rate; key "total"
    pub contrast_failures: u32,
    pub clipped_text: u32,
    pub off_grid_pct: Option<f64>,
    pub auto_layout_coverage: Option<f64>,
    pub nodes_in_scope: u32,
}
pub fn compute(doc: &Document, outputs: &[NodeId], lint: &LintReport) -> DeterministicMetrics;
```

Serialised into the JSONL `run.metrics` object of E15-25 with the same keys (`lint_per_100` flattened as `lint_per_100.<rule>`).

## 8. Edge cases

1. Output frame deleted by the agent before the end: `render_success` 0 for that frame; other metrics use the remaining scope.
2. Zero-node scope: every rate is `null`, `render_success` 0, counts 0.
3. Instances whose main component lives in a library document: instance descendants count for `instance_ratio`; their inherited values are excluded from `token_coverage` (not in scope).
4. Text with mixed runs: font properties count once per distinct run style.
5. Image fills are not bindable (excluded from the denominator), except an E15-48 image-variable binding, which counts as bound.
6. Mask and boolean-operation children: counted as nodes; their fills count.

## 11. Performance budgets

- On a 10k-node output scope: ≤ 300 ms excluding the lint run; linear in N.
- No `to_json` anywhere in metric code (CLAUDE.md §4.1 spirit); renders use the CPU path.
