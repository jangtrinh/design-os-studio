## 1. Summary and user story

As an agent implementing or reviewing a frame, one call gives me the frame's code in my target
language, the design hints a developer would read in Dev Mode (variables with their code names, styles,
component properties, annotations, status) and one screenshot, bounded in size, with an outline
fallback when the code would be too large.

## 2. Current state (FACT)

- `designos_generate_code` returns code only, after cloning the whole document with variables applied
  (`crates/designos-mcp/src/engine.rs:112-128`, clone at `engine.rs:115`).
- Hint data exists in the app (moving to designos-export in T7.3): variables used
  (`crates/designos-app/src/dev/data.rs:109`), component rows (`data.rs:161`), box model (`data.rs:19`);
  annotations and dev status live on `Node.dev` (`crates/designos-doc/src/node.rs:133-134`).
- CSS variable naming follows Figma's sanitizer with fallbacks, e.g. `var(--Color-Primary, #0D99FF)`
  (owner ruling A5; `css_var`, `crates/designos-export/src/codegen.rs:158`).
- Code Connect is a stub (no mappings model yet; T7.15 is outside this pack).

## 3. Behaviour rules

1. Target: `node_id` (required in this pack; selection-default is T7.5, not in this pack).
2. `language`: any `CodeLanguage` id (T7.3), default `css`; `react_tailwind` bool for React.
3. `response_format`: `concise` (default) or `detailed`.
   - concise: code + hint lists without per-node box models.
   - detailed: adds box model per direct child and full annotation property lists.
4. Code is generated from the subtree with bound variables resolved for that subtree only (no
   whole-document clone).
5. Hints:
   - `variables`: every variable used in the subtree (`variables_used`), each with `name`,
     `collection`, `resolved` value in the node's mode, `code_syntax` per platform, and `css`
     (the A5 `var(--Name, fallback)` string);
   - `styles`: linked styles with name, type and values summary;
   - `components`: instances in the subtree with component name, variant and property values
     (`component_rows`);
   - `annotations` and `dev_status` of the root and annotated descendants;
   - `code_connect`: `null` with `"reason": "no mapping model yet (T7.15)"`.
6. Screenshot: one image of the node via T7.1 `render_target` (scale 0.5, long edge 1024).
7. Size bound: if the code exceeds 40,000 characters, or the subtree exceeds 5,000 nodes (codegen
   skipped up front), the reply replaces `code` with the T7.2 XML outline of the node (depth 4,
   1,000 nodes) and sets `truncated: true`, `truncated_reason: "code over 40000 chars" | "subtree over
   5000 nodes"`. Hints and the image are still included.
8. Total structured text stays under 25,000 tokens (≈ 100,000 chars); hint lists are capped at 200
   entries each with a `*_total` count.

## 5. Contracts

Tool `designos_get_design_context` (`readOnlyHint:true, idempotentHint:true`):

```json
{"type":"object","required":["node_id"],"additionalProperties":false,"properties":{
  "node_id":{"type":"integer","minimum":1},
  "language":{"type":"string","default":"css"},
  "react_tailwind":{"type":"boolean","default":false},
  "response_format":{"enum":["concise","detailed"],"default":"concise"},
  "include_screenshot":{"type":"boolean","default":true}}}
```

Output: image content block plus:

```json
{"node_id":40,"language":"css","code":".card { background: var(--Color-Surface, #FFFFFF); ... }",
 "truncated":false,
 "variables":[{"name":"Primary","collection":"Color","resolved":"#0D99FF",
   "code_syntax":{"WEB":"var(--color-primary)"},"css":"var(--color-primary)"}],
 "styles":[],"components":[],"annotations":[],"dev_status":null,
 "code_connect":null,"code_connect_reason":"no mapping model yet (T7.15)",
 "screenshot":{"content_index":0,"width":512,"height":320,"scale_used":0.5}}
```

(`css` uses `codeSyntax.WEB` when set, else the sanitized name with fallback, per A5.)

Errors: `NODE_NOT_FOUND`, `UNKNOWN_LANGUAGE` (`valid_options` = `CodeLanguage::ALL` ids),
`IMAGE_TOO_LARGE` never fails the call (image omitted, `screenshot.skipped` reason).

## 8. Edge cases

1. Node inside an instance: code for the mirror as rendered; `components` names the enclosing
   instance.
2. Variable with no `code_syntax` and an invalid CSS name: sanitized per A5 with fallback.
3. Unsupported language for a node kind (e.g. Android XML for a vector): the generator's own output
   (comment placeholders) is returned unchanged; no error.
4. Huge text content (100k chars) in one node: counts toward the 40k code limit → XML fallback.
5. Scoped Studio canvas shell (empty frame): code for an empty frame plus `scoped: true`.
6. Hidden node: generated as the generators do today (they emit hidden layers or not per target);
   `hidden: true` in the reply.

## 11. Performance budgets

≤ 150 ms for a 2,000-node frame including the screenshot; ≤ 30 ms without screenshot for a 50-node
frame regardless of document size (no whole-document work). Large-fixture frames: bounded by the 5,000
node codegen cap and the T7.2 budget. The MCP runs in its own process, never on Studio's UI thread.
