## 1. Summary and user story

As the owner, I want proven UI-quality skills adopted legally (MIT, attributed, pinned) and made useful on a canvas: every upstream rule mapped to a lint rule or a rubric checklist item, or marked web-only, so agents get rules that design:os can actually check.

## 3. Behaviour rules

1. **Vendor copy.** Copy the upstream `skills/` tree, `LICENSE` and `README.md` at the pinned commit byte for byte into `skills/vendor/jakubkrehel-skills/upstream/`. `UPSTREAM.toml` records `repo`, `commit`, `fetched_on`, and the SHA-1 of every copied file.
2. **Attribution.** `ATTRIBUTION.md`: "Portions of this folder are copied from or derived from jakubkrehel/skills (https://github.com/jakubkrehel/skills), commit 4c66b1f…, Copyright (c) 2026 Jakub Krehel, MIT License (see LICENSE)." The same text goes into `THIRD_PARTY_LICENSES.md` through the E15-23 register (`use = "ship-in-skills"`).
3. **Rule extraction.** A rule is each top-level bullet or numbered item in a topic file or in a `SKILL.md` body section (not frontmatter, not headings, not code blocks). Rule id = `<skill>/<file stem>#<n>` with `n` the 1-based ordinal of the item in that file at the pinned commit. The extractor (`scripts/check_vendor_skills.py extract`) lists every rule with its text; its output is committed as `rules.lock` so ordinals cannot drift silently.
4. **Mapping.** `rule-map.toml` has exactly one entry per extracted rule (AC2):
   - `map = "lint:<rule id>"` when a unified linter rule checks it (E15-9 registry id);
   - `map = "rubric:<axis>"` or `map = "check:<surface rule id>"` when the critique rubric or a surface checklist covers it;
   - `map = "skill:<our skill>/<section>"` when it becomes agent guidance in E15-47 without a deterministic check;
   - `map = "web-only"` with `reason` when it has no meaning on a canvas (keyboard focus order, ARIA attributes, CSS performance);
   - `canvas_text`: our rewrite of the rule for the canvas (for everything not `web-only`), for example upstream "use OKLCH for palette generation" → "Derive palette steps by OKLCH lightness, keep chroma per hue; check with `designos_lint` contrast". `canvas-rules.md` is generated from `canvas_text` entries grouped by skill, with the attribution header.
5. **Licence gate (AC1, AC3).**
   - `LICENSE` in the vendor folder must equal the upstream file at the pinned commit (SHA-1 in `UPSTREAM.toml`, verified by `scripts/check_vendor_skills.py verify`, which compares against the committed hash; an optional `--online` mode refetches from GitHub);
   - every file under `skills/vendor/` must belong to a folder with a register entry whose licence is not `NONE`;
   - any file whose path or content names `transitions.dev` or another excluded source fails the check.
6. **Serving.** Vendored skills are not attached to agents verbatim. E15-47's skills reference `canvas-rules.md` sections; the Studio skill picker (#573) lists `jakubkrehel UI rules (canvas)` as one bundled skill whose text is `canvas-rules.md` plus the attribution line.

## 4. Data model / schema

```toml
# rule-map.toml
[meta]
upstream_commit = "4c66b1fa86e9ab70187b43d7da9b6fdb29f2ef63"

[[rule]]
id = "better-colors/contrast#2"
text_sha1 = "…"            # of the upstream rule text, so edits to rules.lock are caught
map = "lint:<E15-10 contrast rule id>"
canvas_text = "Body text needs 4.5:1 against the colour actually behind it; designos_lint measures the resolved backdrop."

[[rule]]
id = "better-accessibility/focus-and-keyboard#1"
map = "web-only"
reason = "Keyboard focus order has no canvas meaning; prototypes are out of this rule's scope."
```

## 5. Contracts

`python3 scripts/check_vendor_skills.py verify | extract | map-coverage`:
- `verify`: licence and file hashes; exit 1 lists `licence-mismatch`, `file-hash-mismatch`, `unlicensed-file`;
- `extract`: regenerates `rules.lock`; CI fails if it differs from the committed file;
- `map-coverage`: every rule mapped exactly once, every `lint:` id exists in the E15-9 rule registry (read through whatever listing E15-9 exposes; if it exposes none, this task adds `designos-mcp --list-lint-rules`, printing one registry id per line), every `check:` id exists in E15-21 data; exit 1 lists `unmapped-rule`, `unknown-lint-id`, `duplicate-mapping`.

## 8. Edge cases

1. Upstream adds skills after the pin: ignored until a reviewed re-pin; re-pinning regenerates `rules.lock` and the map shows new unmapped rules.
2. A rule that is half canvas, half web: map to the canvas part with `canvas_text`, note the web part in `reason`.
3. `agents/openai.yaml` files: copied (part of the upstream tree) but not used.
4. Upstream text containing links to third-party tools: kept in the vendor copy as is (it is upstream content); our `canvas_text` never names a third-party design tool other than Figma.
5. Hash mismatch from line-ending conversion on Windows checkouts: `.gitattributes` marks `skills/vendor/**` as `-text` so bytes stay identical.
