## 1. Summary and user story

As a designer (or a variant agent, E15-36), I create a branch of a file: a full working copy with the
same node ids, forked from a "Branch point" version of main, that lives with the file (not as another
file in Home), so it can later be diffed and merged.

## 2. Current state (FACT)

- Library files are `FileEntry { id, project, folder, name, created, modified, opened, starred,
  thumbnail }` in the library manifest (`crates/designos-library/src/store.rs:45-58`).
- Versions are full snapshots under `versions/<file-id>/<n>.designos` with
  `versions/<file-id>/index.json` (`crates/designos-library/src/versions.rs:1-18`), written atomically;
  `save_version_described(file_id, doc, label, description, auto)` returns a `FileVersion { n, label,
  description, auto, created, size }` (`versions.rs:35-51`, `143`). Named versions are kept forever
  (`versions.rs:10-14`).
- No branch concept exists.

## 3. Behaviour rules

1. Ruling R5.19 places branches inside the file: they belong to the file's library entry, are listed by
   that file's branch switcher, and never appear as separate Home files (Home shows a branch count on
   the file card).
2. Layout under the library root:
   ```text
   branches/<file-id>/<branch-id>.designos   working copy of the branch
   ```
   Metadata lives in the file's manifest entry: `FileEntry.branches: Vec<BranchMeta>`.
3. `BranchMeta { id, name, base_version: u32, created, modified, author, status: Active | Archived |
   Merged { into_version: u32 }, description }`.
4. Create branch: (a) save a named version on main labelled `Branch point: <name>` (its `n` becomes
   `base_version`); (b) write the current main document unchanged as the branch copy, so every `NodeId`
   is identical; (c) append the `BranchMeta`; all three under the existing manifest write lock; on any
   failure the partial files are removed and the manifest is unchanged.
5. Open branch: loads `branches/<file-id>/<branch-id>.designos`; saving writes the same path
   atomically and updates `modified`.
6. Archive/restore: status change only; archived branches are read-only (open in view mode); restore
   sets `Active`. Delete moves the branch copy to the trash (never hard-deleted, as versions).
7. Branch versions: saving a version while a branch is open stores it under
   `versions/<file-id>~<branch-id>/` (same mechanism, separate index), so branch history never mixes
   with main's.
8. Legacy manifests without `branches` load (serde default) and save without the key when empty.
9. Files opened from outside the library (plain paths) cannot branch; the action explains "Save to your
   library to create branches".

## 4. Data model / schema changes

- `FileEntry.branches: Vec<BranchMeta>` with `#[serde(default, skip_serializing_if = "Vec::is_empty")]`.
- `Library::{create_branch(file_id, doc, name, author) -> BranchMeta, list_branches, load_branch,
  save_branch, archive_branch, restore_branch, delete_branch, branch_path}` in `branches.rs`.

## 5. Contracts

Library API only in this task (UI is T10.4, outside this pack). Errors (Rust `Result` with typed
`BranchError`): `NotALibraryFile`, `NameTaken`, `BranchArchived` (save refused), `NotFound`, IO errors
with the path.

## 6. File-format mapping

Branch copies are ordinary `.designos` documents; nothing new inside the document format.

## 7. UI

None in this task (T10.4 branch UI: title-bar switcher, Home count). E15-36 uses the API headlessly.

## 8. Edge cases

1. Two branches with the same name: refused (`NameTaken`), case-insensitive.
2. Crash between version save and branch copy write: the named version remains (harmless, labelled);
   no `BranchMeta`; retry creates a new branch point.
3. Main file deleted (trashed): its branches move to the trash with it and restore with it.
4. Duplicating a file (`duplicate_file`, `store.rs:482`): branches are not duplicated; the duplicate
   starts with none.
5. Version retention (`versions.rs:66-75`): branch points are named versions, so retention never drops
   a base.
6. Branch of a branch: not supported in this pack; the action is unavailable while a branch is open.

## 9. Non-goals

- Diff and merge (T10.2, T10.3), branch UI (T10.4), comments across branches (T10.10).

## 10. Test plan

Seam: designos-library tests with a temporary root.

| Case | Expected |
|---|---|
| `create_saves_branch_point_and_same_ids` | create branch → named version `Branch point: X` exists with `n == base_version`; branch copy node id set equals main's |
| `legacy_index_loads` | manifest JSON without `branches` loads; saving an unchanged entry writes no `branches` key |
| `archived_is_read_only` | archive, then `save_branch` → `BranchArchived` |
| `branch_versions_separate` | version saved on the branch appears only in the branch index |
| `failure_leaves_manifest_unchanged` | inject write failure on the copy → no `BranchMeta`, no copy file |

## 11. Performance budgets

Create branch = one version snapshot + one copy write: two serialisations of the document, done off the
UI thread by callers (the UI never calls `to_json` on its thread, CLAUDE.md §4.1). Recorded for the
large fixture in the PR.

## 13. Owner rulings
