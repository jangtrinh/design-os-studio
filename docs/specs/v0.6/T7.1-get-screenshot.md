## 1. Summary and user story

As an agent, I ask for a small image of a node, a set of nodes or a page-space rectangle and receive
it inline as MCP image content, already downsized to a sensible long edge, with the scale that was
used, so I can look at my work without writing files.

## 2. Current state (FACT)

- `designos_render_png` only writes a new file in the workspace (`crates/designos-mcp/src/server.rs:469-496`,
  descriptor `server.rs:625`); nothing is returned inline.
- Rendering: `designos_export::render_export(doc, node, scale)` clamps scale to 0.01..=32 and renders
  the node's render bounds (`crates/designos-export/src/raster.rs:82-100`); `export_png`
  (`raster.rs:172`), `export_jpg` (`raster.rs:181`).
- Pixmap caps: `MAX_PIXMAP_SIDE = 16_384`, `MAX_PIXMAP_PIXELS = 1 << 28`, enforced by
  `checked_pixmap_size` which returns `None` instead of aborting (`crates/designos-render/src/lib.rs:139-157`).
  `render_png` reports that as "produced an empty image" (`server.rs:481-483`), not as a size error.
- The session renders on a document with bound variables applied (`server.rs:476`,
  `designos_doc::apply_bound_variables`, `crates/designos-doc/src/variables_apply.rs:306`), which
  clones the whole document.

## 3. Behaviour rules

1. Target, exactly one of:
   - `node_id`: render bounds of that node (effects and strokes included, as `render_export`);
   - `node_ids` (1..=50): union of their render bounds, all on the same page, else
     `NODES_ON_DIFFERENT_PAGES`;
   - `region: {page_id, x, y, width, height}` in page space; width and height > 0.
2. Scale: `scale` requested (0.25..=4, default 0.5).
3. Long-edge cap: `max_long_edge` (64..=4096, default 1024). If
   `max(width, height) * scale > max_long_edge`, the used scale becomes
   `max_long_edge / max(width, height)`; the reply states `scale_used` and `downscaled: true`.
   `max_long_edge: 0` disables the cap (the caller wants exact `bounds x scale`).
4. Size rule: the image is `ceil(width * scale_used)` x `ceil(height * scale_used)` px (within 1 px of
   bounds x scale).
5. Hard cap: if the size fails `checked_pixmap_size` or `scale_used < 0.01`, fail with
   `IMAGE_TOO_LARGE` (named error, `valid_options` lists the largest allowed scale and a suggested
   `max_long_edge`). Nothing is ever cropped or truncated silently.
6. Rendering uses the deterministic CPU path; bound variables are resolved for the rendered subtree
   only (resolve per node with `resolved_node`, `variables_apply.rs:300`), not a whole-document clone.
7. Format: `png` (default) or `jpeg` (quality 1..=100, default 80, flattened on white as
   `export_jpg`).
8. Hidden target node: rendered as the engine renders it (empty or transparent), reply
   `visible: false`; no error.

## 5. Contracts

Tool `designos_get_screenshot` (annotations `readOnlyHint:true, idempotentHint:true`).

Input:

```json
{"type":"object","additionalProperties":false,"properties":{
  "node_id":{"type":"integer","minimum":1},
  "node_ids":{"type":"array","items":{"type":"integer","minimum":1},"minItems":1,"maxItems":50},
  "region":{"type":"object","required":["page_id","x","y","width","height"],"additionalProperties":false,
    "properties":{"page_id":{"type":"integer","minimum":1},"x":{"type":"number"},"y":{"type":"number"},
                  "width":{"type":"number","exclusiveMinimum":0},"height":{"type":"number","exclusiveMinimum":0}}},
  "scale":{"type":"number","minimum":0.25,"maximum":4,"default":0.5},
  "max_long_edge":{"type":"integer","minimum":0,"maximum":4096,"default":1024},
  "format":{"enum":["png","jpeg"],"default":"png"},
  "quality":{"type":"integer","minimum":1,"maximum":100,"default":80}}}
```

Output: `content[0]` = `{"type":"image","mimeType":"image/png","data":"<base64>"}`;
`structuredContent`:

```json
{"target":{"node_id":12},"page_id":1,"bounds":{"x":0,"y":0,"width":4000,"height":2400},
 "scale_requested":0.5,"scale_used":0.256,"downscaled":true,"width":1024,"height":615,
 "format":"png","bytes":183422,"visible":true}
```

Errors: `NODE_NOT_FOUND`, `NODES_ON_DIFFERENT_PAGES`, `INVALID_REGION`, `IMAGE_TOO_LARGE`,
`EXACTLY_ONE_TARGET` (none or several of node_id/node_ids/region). All `safe_to_retry: true`.

`designos_render_png` stays (file output) and gains the same `IMAGE_TOO_LARGE` error instead of
"produced an empty image".

## 8. Edge cases

1. Region partly outside every node: renders the page background colour there (as `render_page`).
2. Region on a page that is a scoped shell in a Studio session (`live_canvas_scope.rs`): renders what
   the scoped canvas holds; reply adds `scoped: true` when the page holds empty frame shells.
3. Node with a huge drop shadow: bounds include the effect, as `render_bounds` does.
4. `max_long_edge` smaller than needed for a 1 px tall line: image is at least 1 px tall.
5. `scale: 4` on a 3000 px frame with cap 0: 12000 px edge passes the side cap but may fail the pixel
   cap → `IMAGE_TOO_LARGE` with the largest allowed scale.
6. Text with fonts not installed: rendered with the same fallback as Studio (bundled fonts first).

## 9. Non-goals

- GPU rendering in the MCP process.
- Video or animated output.

## 11. Performance budgets

Render of a 1024 px long-edge image of a 2,000-node frame: under 250 ms release on the reference
machine; per-subtree variable resolution, never a full-document clone (the whole-document clone in
`render_png` is replaced by the same helper). Base64 encoding adds about 33% to bytes; the 1024 default
keeps typical replies under 300 KB.
