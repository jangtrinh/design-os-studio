## 1. Summary and user story

As Studio's web-capture importer (and later the browser extension), I run one self-contained script in a
page and get a JSON capture of what is on screen: element boxes, the computed styles that matter for
layout and paint, text runs with their line boxes, images as data URLs, the CSS custom properties behind
values and framework component-name hints.

## 3. Behaviour rules

1. `capture.js` is framework-free ES2020, exposes `window.__designosCapture(options) -> Promise<Capture>`,
   uses only standard DOM APIs, and never modifies the page.
2. Walk: depth-first over the DOM from `document.documentElement` (or `options.root` selector), in paint
   order approximated by DOM order plus `z-index` stacking contexts (each element records `z` = its
   paint index computed from stacking context order). Skipped: `display:none`, `visibility:hidden`
   subtrees (recorded with `visible:false` only when `options.include_hidden`), `<script>`, `<style>`,
   `<template>`, `<noscript>`, `<head>` contents.
3. Per element: `tag`, `id`, `classes`, `role`, `aria_label`, `alt`, `box` (border box in page
   coordinates, `getBoundingClientRect` + scroll offsets), `content_box`, `styles` (computed subset
   below, values as computed strings), `pseudo.before` / `pseudo.after` when they render content or a
   box, `children`.
4. Computed subset: `display, position, top/right/bottom/left, z-index, flex-direction, flex-wrap,
   justify-content, align-items, align-content, align-self, flex-grow, flex-shrink, flex-basis, gap,
   row-gap, column-gap, grid-template-columns, grid-template-rows, grid-column, grid-row, padding-*,
   margin-*, border-*-width/style/color, border-*-radius, background-color, background-image,
   background-size, background-position, background-repeat, box-shadow, opacity, overflow-x/y,
   transform, transform-origin, color, font-family, font-size, font-weight, font-style, line-height,
   letter-spacing, text-align, text-decoration-line, text-transform, white-space, word-break,
   text-overflow, -webkit-line-clamp, object-fit, mix-blend-mode, filter, backdrop-filter, visibility`.
5. Text runs: for each text node, one run per contiguous style, with `text`, `styles` (font subset),
   and `lines` = the client rects of the run (from `Range.getClientRects()`), so the importer knows
   wrapping exactly.
6. Images: `<img>`, CSS `background-image: url()`, `<picture>` current source, `<canvas>`
   (`toDataURL`), inline `<svg>` (serialised `outerHTML`), `<video>` poster. Bitmaps are embedded as
   data URLs: drawn to a canvas when same-origin; otherwise fetched with `fetch(src, {mode:'cors'})`;
   if blocked, recorded as `{src, blocked: true}` (never silently dropped). Limits: 50 MB of image data
   per capture, then remaining images are `{src, skipped: "size limit"}`.
7. CSS custom properties (E15 extension): each element records (a) `css_vars_declared`: custom
   properties whose computed value differs from the parent's (declared or overridden here), and (b)
   `css_var_refs`: for each captured property whose winning declaration uses `var(--x, ...)`, the
   property → variable name chain, found by matching readable stylesheet rules (`element.matches`
   on `CSSStyleRule.selectorText`, specificity and source order) and inline styles. Cross-origin
   stylesheets that cannot be read are listed in `css_vars_unavailable: [href]`.
8. Framework hints (E15 extension): `component_hint` = the nearest component name from React fiber
   (`__reactFiber$*` keys → `type.displayName || type.name`), Vue (`__vueParentComponent.type.name` or
   `__name`), Svelte dev metadata (`__svelte_meta`), Angular (`ng-version` root and the host element's
   component selector), or a `data-component` attribute. Absent → omitted.
9. Budget: at most `options.max_elements` (default 20,000) elements; beyond it `truncated: true` with
   the count of skipped elements.
10. Output envelope: `{schema: "designos-webcapture", version: 1, url, title, viewport: {width,
    height, dpr}, scroll: {width, height}, captured_at, fonts: [loaded font faces with family, weight,
    style, src when readable], root, truncated, stats}`.

## 4. Data model / schema changes

`src/schema.rs`: serde types for the envelope (`Capture`, `Element`, `TextRun`, `ImageRef`, `Pseudo`)
with `deny_unknown_fields` off for forward compatibility and a `version` check (unknown major →
`UnsupportedCaptureVersion`). The JS and Rust schemas are tested against each other (3.10 fixtures).

## 5. Contracts

- JS API: `__designosCapture({root?, include_hidden?, max_elements?, max_image_bytes?})`.
- Rust: `designos_webcapture::Capture::from_json(&str) -> Result<Capture, CaptureError>`.
- No MCP tool in this pack (T7.14 code-to-canvas comes later); no network by Studio itself.

## 6. File-format mapping

The capture JSON is an interchange file (`.capture.json`); it is never stored in documents.

## 7. UI

None (T8.26 extension and Studio import UI are elsewhere; T8.27 adds the import entry).

## 8. Edge cases

1. Shadow DOM: open shadow roots are walked (children recorded under the host with `shadow: true`);
   closed roots are recorded as opaque boxes.
2. iframes: same-origin iframes captured recursively with an offset; cross-origin recorded as boxes
   with `cross_origin: true`.
3. Sticky/fixed elements: boxes at the current scroll position; `position` recorded.
4. Lazy images not yet loaded: the script waits up to `options.image_timeout_ms` (default 3,000) for
   `img.decode()`; still pending → `{src, pending: true}`.
5. Huge single text node (100k chars): runs split by style only; `lines` capped at 2,000 rects with
   `lines_truncated`.
6. Pages that override `Array.prototype` or `window.fetch`: the script captures references to native
   functions at load before use, falling back to recording `blocked` images.

## 10. Test plan

Seam: Playwright on local fixture pages written by us (`tests/playwright/fixtures/*.html`), served from
the file system, no network.

| Case | Expected |
|---|---|
| `boxes_styles_runs_images` | fixture card page → capture has the card element with box equal to Playwright's `boundingBox()` (±0.5 px), computed `display:flex`, a text run with 2 line rects for a wrapping paragraph, and an image as a `data:image/png;base64` URL |
| `css_var_refs` (amendment) | `:root{--brand:#0d99ff} .btn{background:var(--brand)}` → button `css_var_refs["background-color"] == ["--brand"]` |
| `component_hint` (amendment) | fixture with a tiny React-like fiber stub on an element → `component_hint == "PricingCard"` |
| `cross_origin_image_blocked_recorded` | image from an unreachable origin → `{src, blocked:true}` |
| `rust_parses_capture` | every fixture capture parses with `Capture::from_json` |
| `truncation` | `max_elements: 10` → `truncated:true` and a count |

## 11. Performance budgets

A 5,000-element page captures in ≤ 1.5 s (excluding image fetches) in headless Chromium; recorded. The
script does no layout-thrashing writes (reads only).
