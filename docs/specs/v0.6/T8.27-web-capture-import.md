## 1. Summary and user story

As a designer, I import a captured web page and get real design layers: flex and grid containers as
auto layout, text as editable text with the page's fonts and wrapping, images as image fills, borders,
radii, shadows and gradients as native properties, so the import renders like the page and stays
editable.

## 2. Current state (FACT)

- No importer exists. The document model supports what the mapping needs: auto layout with direction,
  wrap, gaps, padding, alignments, sizing and grid tracks (`AutoLayout`, `crates/designos-doc/src/node.rs:859-890`),
  child sizing/absolute/margins (`LayoutChild`, `node.rs:961-987`), text with runs and auto-resize
  (`TextProps`, `node.rs:589-620`; `TextAutoResize`, `crates/designos-doc/src/paint.rs:401-407`),
  gradient and image paints (`PaintKind`, `paint.rs:188-210`).
- SVG import exists: `crates/designos-svg` maps usvg trees to nodes.
- The pixel diff library: `crates/designos-diff/src/lib.rs` (`compare`, `diff_image`, `DiffOptions`).

## 3. Behaviour rules

### 3.1 Structure

- Root: a frame named `<title> — <url host>` sized to the capture viewport width and the scroll height,
  clipping content, at a free spot on the current page.
- Each captured element with a visible box, background, border, shadow or children becomes a frame;
  pure inline wrappers without their own paint are flattened into their parent's text runs.
- Names: `component_hint` when present, else `aria_label`, else `#id`, else first class, else tag.

### 3.2 Layout mapping

| Capture | Document |
|---|---|
| `display:flex` | auto layout, direction from `flex-direction` (row/column; `-reverse` keeps visual order by reversing children), `gap` → item spacing, `row-gap` → counter spacing with `flex-wrap: wrap` → wrap, padding |
| `justify-content` | primary align: start/flex-start/normal → Start, center, end/flex-end → End, space-between, space-around, space-evenly |
| `align-items` | counter align: start, center, end, baseline; `stretch` → children Fill on the counter axis unless they have an explicit size |
| child `flex-grow > 0` | Fill on the primary axis; explicit width → Fixed; otherwise Hug when the box equals its content size |
| `display:grid` | grid auto layout with column/row counts and track sizes from the computed templates |
| block flow (`display:block` children stacked) | inferred column auto layout when children do not overlap, their left edges match within 1 px and the gaps vary by ≤ 1 px (gap = median); otherwise children placed absolutely |
| `position:absolute/fixed` | `layout_child.absolute = true` with page-relative offsets converted to parent space |
| margins between flex children | added to the spacing when uniform; otherwise `layout_child.margin` |
| `overflow:hidden` | clips content |

### 3.3 Paint and effects

Background colour → solid fill; linear/radial gradients → gradient paints (angle and stops converted to
handles); background images → image fills with `background-size` → fit/fill/tile; borders → stroke
(uniform) or per-side stroke weights; border radius → corner radii; `box-shadow` → drop/inner shadows;
`opacity` → node opacity; `mix-blend-mode` → blend; `filter: blur()` → layer blur;
`backdrop-filter: blur()` → background blur; transforms → rotation/scale when representable, else the
element's box is used and the transform recorded in a note.

### 3.4 Text

- Each text-bearing element becomes one text node with runs (font family, size, weight, style, line
  height, letter spacing, colour, decoration, case transform), editable.
- Auto-resize: `white-space: nowrap` or a single line rect → width-and-height; wrapping text →
  Height with the captured width; `-webkit-line-clamp` → Truncate with `max_lines`.
- Fonts: the family list is matched against available fonts (bundled, system, on-demand fetch through
  designos-fonts); the first available is used and substitutions are reported.

### 3.5 Images and vectors

Data-URL bitmaps → document images (deduplicated by hash); inline SVG → designos-svg import as a
vector group; blocked or skipped images → a rectangle with a neutral fill named `Image (not captured:
<reason>)` (reported, never silently empty).

### 3.6 Report and undo

The import is one undo step. The report lists element count, nodes created, flattened wrappers,
absolute fallbacks with reasons, font substitutions, images not captured, unsupported CSS (with the
property and element), so nothing vanishes silently.

## 8. Edge cases

1. Negative margins causing overlap in a flex row: falls back to absolute children for that container,
   reported.
2. Text with mixed inline elements (links, `<strong>`): one text node with runs; link `href` stored as
   the run's hyperlink when the model supports it, else noted.
3. CSS `order` property: children placed in visual order (by box position along the axis).
4. Elements wider than the viewport (horizontal scroll): root frame width = scroll width.
5. `transform: scale()` on a flex child: box size used, scale noted.
6. Capture with `truncated: true`: import proceeds and the report says the page was truncated.

## 9. Non-goals

- Tokens from CSS variables (E15-43), components from repeated subtrees (E15-44), responsive captures
  (T8.28).

## 11. Performance budgets

Import of a 5,000-element capture ≤ 1 s off the UI thread (Studio runs it on a worker and applies the
command on the UI thread), excluding font downloads.
