## 1. Summary and user story

As a developer or agent, I generate a standalone HTML page (markup plus a `<style>` block) for a frame,
with auto layout as flexbox/grid and bound variables printed as their code syntax, which validates and
opens in a browser as is.

## 2. Current state (FACT)

- Code targets: CSS, Tailwind, React, SwiftUI, UIKit, Compose, Android XML
  (`crates/designos-app/src/dev/mod.rs:18-32`; MCP list `crates/designos-mcp/src/engine.rs:116-126`).
  No HTML target; `crates/designos-export/src/` has no `html.rs`.
- CSS generation with paints, text styles and fonts: `css_for` (`crates/designos-export/src/css.rs:10`),
  `paint_css` (`css.rs:261`), `text_style_css` (`css.rs:388`), `font_family_css` (`css.rs:379`).
- CSS variable references follow ruling A5: `var(--Color-Primary, #0D99FF)`, `codeSyntax.WEB` wins
  (`css_var`, `crates/designos-export/src/codegen.rs:158`).
- SVG export for vectors: `export_svg` (used by MCP at `engine.rs:124`). Fixture card:
  `crates/designos-export/src/codegen.rs:697`.

## 3. Behaviour rules

1. Output: a complete document by default (`<!doctype html>`, `<html lang="en">`, `<meta
   charset="utf-8">`, `<meta name="viewport" content="width=device-width, initial-scale=1">`,
   `<title>` = layer name, one `<style>`, `<body>` containing the root element). Option `fragment:
   true` returns only the root element and its `<style>`.
2. Elements: frames, groups, components, instances, sections → `<div>`; text → `<p>` (multi-paragraph
   text → one `<p>` per paragraph inside a `<div>`), runs → `<span>` with their own class; image-filled
   rectangles → `<img alt="<layer name>">` with a data URL; vectors, boolean ops, stars, polygons,
   lines → inline `<svg>` from `export_svg`; ellipses → `<div>` with `border-radius: 50%`. Hidden
   layers are omitted.
3. Classes: one class per node, from the sanitized layer name (lower-case, `[a-z0-9-]`, prefixed `n-`
   when starting with a digit), de-duplicated with `-2`, `-3` suffixes. Style rules come from the same
   functions `css_for` uses, so CSS and HTML targets never disagree.
4. Layout: auto layout row/column → `display:flex` with `flex-direction`, `gap`, `padding`,
   `justify-content`, `align-items`, `flex-wrap`, `row-gap`; grid → `display:grid` with track templates;
   hug → `width: fit-content` (or `height`), fill → `flex: 1 1 0` on the primary axis and
   `align-self: stretch` on the counter axis, fixed → px; absolute children → `position:absolute` with
   `left/top` and the parent `position:relative`; frames without auto layout place children
   absolutely.
5. Text: font family (with generic fallback), size, weight, line height, letter spacing, colour,
   alignment; `auto_resize` none → fixed width and height with `overflow:hidden`; truncate → ellipsis
   (`-webkit-line-clamp: <max_lines>` with `display:-webkit-box`).
6. Variables (A5, A7): a bound property prints `var(--<name>, <resolved fallback>)`, the name from
   `codeSyntax.WEB` when set, else the sanitized variable name. A `:root { --<name>: <default-mode
   value>; }` block declares every used variable; a node with an explicit mode gets inline custom
   property overrides for that mode's values.
7. Escaping: text content and attribute values are HTML-escaped; no script, no event handlers, no
   external URLs.

## 8. Edge cases

1. Layer names producing empty classes (emoji only): `n-<id>`.
2. Image fill with crop/tile modes: `object-fit` cover/contain/fill mapping; tiled images use a
   background on a `<div>` instead of `<img>`.
3. Rotation: `transform: rotate(<deg>)` with `transform-origin` matching the node's origin.
4. Mixed-direction text (RTL paragraphs): `dir="rtl"` on the paragraph.
5. Instance of a library component: plain markup (no component framework); a comment names the
   component.
6. Very large subtree (5,000 nodes): generated; T7.4 applies its own size fallback.

## 9. Non-goals

- Framework targets (Vue T7.28, Web Components T7.30) and Code Connect mapping.
- Interactions and prototype links.

## 10. Test plan

Seams: designos-export snapshot tests plus html-validate.

| Case | Expected |
|---|---|
| `card_snapshot` | fixture card → output equals committed snapshot |
| `card_passes_html_validate` | snapshot validated with `html-validate` (recommended preset) in the CI job `codegen-validators` (Node available); the job fails on any error; locally the test is `#[ignore]` with the command in its doc comment, never silently skipped in CI |
| `bound_variables_print_code_syntax` | fill bound to a variable with `codeSyntax.WEB = var(--brand-primary)` → `var(--brand-primary, #0D99FF)`; without code syntax → `var(--Color-Primary, #0D99FF)` |
| `auto_layout_to_flex` | row with gap 12, padding 16 → `display:flex; flex-direction:row; gap:12px; padding:16px` |
| `escaping` | text `<b>&` → `&lt;b&gt;&amp;` |
| `language_listed_once` | `CodeLanguage::ALL` contains Html; MCP enum includes `html` with no hand-edited list |

## 11. Performance budgets

Same order as `css_for`: ≤ 20 ms for a 2,000-node frame (excluding image data URL encoding, which is
O(bytes)).
