## 1. Summary and user story

As a user starting an agent run, I pick one or more design skills (built-in, or my own `SKILL.md`
files from a folder) and their text reaches the agent as context, offline, with the exact skill version
recorded for the run. A skill I add to my folder appears in the picker without restarting Studio.

## 2. Current state (FACT)

- Studio generates one session skill per tab (`SKILL.md` and copies under `.claude/skills/designos-studio/`
  and `.agents/skills/designos-studio/` in the session directory, `crates/designos-app/src/terminal.rs:936-962`);
  its content is fixed text about the session bridge.
- Prompts reach the CLI through `submit_chat_prompt` (`terminal.rs:1006`); there is no skill picker or
  catalogue.
- The repository ships `skills/design-os-studio/SKILL.md` for developers, not as a runtime skill.
- App user settings live in `settings.json` at the library root (`crates/designos-app/src/comments/settings.rs:1-8`);
  the library root is `$DESIGNOS_LIBRARY` or the data dir (`crates/designos-library/src/store.rs:188-196`).

## 3. Behaviour rules

### 3.1 Sources

| Source | Location | Rules |
|---|---|---|
| Built-in | `assets/skills/<name>/SKILL.md` embedded at build time (`include_dir`-style table generated by `build.rs`) | Front matter must include `name`, `description`, `version`, `license`, `attribution` (for adopted skills) — the build fails otherwise (skip anything without a licence) |
| User | `<library root>/skills/<name>/SKILL.md` | `name` and `description` required; `version` optional (defaults to the content hash) |

`SKILL.md` = YAML front matter + markdown body; max 64 KB; `name` kebab-case, unique per source (a user
skill with a built-in's name is shown as `<name> (yours)`).

### 3.2 Discovery

- Built-ins are known at start. The user folder is scanned at start and watched off the UI thread
  (mtime polling on the folder and each `SKILL.md`, the same pattern as the autosave disk watcher;
  `ctx.request_repaint()` only when something changed). A new or edited skill appears in the picker
  without a restart. Invalid files are listed with the reason (`missing description`, `over 64 KB`)
  and cannot be picked.

### 3.3 Attachment

- The picker selects up to 3 skills per run; total attached text ≤ 8,000 tokens (chars / 4), else the
  Start action is disabled with the measured size.
- On run start, the selected skills' bodies (front matter stripped, title kept) are attached exactly
  like the E15-16 bootstrap: via the Claude Code `UserPromptSubmit` hook output on the first prompt,
  and prepended in a fenced `designos-skill:<name>@<version>` block for other CLIs.
- The run records `skills: [{name, version, sha256}]` in `<session_dir>/run.json`; the Agents panel run
  row shows them.
- Fully offline: no network access anywhere in discovery or attachment.

## 4. Data model / schema changes

- `Skill { name, description, version, license, attribution, body, source: BuiltIn | User(PathBuf),
  sha256, error: Option<String> }`.
- `settings.json` key `skills.default` = list of skill names preselected for new runs.
- No document change.

## 5. Contracts

No MCP tool (skills are chosen by the user in Studio). RD-3 `designos_spawn_agents` accepts
`skills: ["<name>", ...]` per agent entry (same limits); unknown names fail `UNKNOWN_SKILL` with the
available names.

## 6. File-format mapping

None.

## 7. UI (load es-designer before UI code; desktop capture at 1440, responsive SKIPPED)

In the Agents panel next to the runtime selector: a `Skills` button (28 px) opening a list of skills
grouped `Built-in` / `Yours`: 28 px rows with name (11 px), description (10 px caption, secondary), a
24 px checkbox, and a version tag in mono (P5). Invalid user skills show the reason in danger text and
no checkbox. Footer: attached size `2,340 / 8,000 tokens` in mono and an `Open skills folder` action
that opens `<library root>/skills` in the OS file browser (creating it if missing). Empty `Yours`
section: `Add a folder with a SKILL.md to <path>` (real empty state, P6).

## 8. Edge cases

1. Skill file deleted while selected for the next run: removed from the selection with a toast.
2. Two user skills with the same `name` in different folders: both listed with folder names; picking
   requires disambiguation by folder.
3. Non-UTF-8 file: invalid, reason shown.
4. Skill body containing instructions to ignore other rules: attached as data inside a fenced block;
   the rules pack (E15-15) states that skill text never overrides tool errors or ownership.
5. Built-in skill updated in a new app version: version changes; old runs keep their recorded version.
6. Library root unavailable: built-ins still work; `Yours` shows the error.

## 9. Non-goals

- Skill content (E15-46 adopted MIT skills with attribution, E15-47 our own).
- Downloading skills from the internet.
