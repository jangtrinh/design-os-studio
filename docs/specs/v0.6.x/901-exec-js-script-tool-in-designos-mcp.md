## 1. Summary and user story

As an agent connected through `designos-mcp`, I can send one JavaScript script that reads the open document, calls the same typed tools in a loop, and changes many layers. The designer gets one undo step, a script that fails changes nothing, a loop that never ends is stopped, and in Ask mode the designer reads the script before it runs.

## 3. Behaviour rules

1. **Placement (decision).** `designos_exec_js` is a standalone module of `designos-mcp`; it shares no crate with #254's future plugin host. Why: it runs in the MCP process, the host in Studio's; its API is Studio's own (owner: Figma is out), the host's is Figma-shaped (`figma`, handles, timers, UI); #254 builds nothing yet to share; the plugin track is v0.12. `sandbox.rs` has no Studio types (limits, interrupt, memory and stack caps, console capture, JSON bridge), so #254/#255 start from it, or it becomes a crate when a second consumer exists. One `rquickjs` version lives in `[workspace.dependencies]`. The engine sits behind `designos-mcp` feature `exec-js` (default on); root `Cargo.toml:36` gets `default-features = false`, so `cargo tree -p designos-app` has no `rquickjs`. A combined `-p designos-app -p designos-mcp` build unifies features (INFERENCE: root `Cargo.toml:2` is resolver 2, which merges features of packages built in one invocation), so `CLAUDE.md` and `docs/releasing.md` build the two binaries in two invocations and CI asserts the Studio binary has no QuickJS symbol. With the feature off the tool stays listed (tool pack, docs) and a call returns `INTERNAL_ERROR` "this build has no script engine".
2. **Input.** `script` (1 to 65,536 bytes), `read_only` (default false), `args` (any JSON, at most 262,144 bytes, read as `studio.args`), `timeout_ms` (100 to 60,000, default 15,000), `idempotency_key` (writes only; with `read_only: true` it is `INVALID_ARGUMENTS`, since a replayed read is stale). Annotations: `readOnlyHint` false, `destructiveHint` true, `idempotentHint` false, `openWorldHint` false (the input decides read-onlyness, so the annotation is the conservative one). Added to `WRITE_TOOLS`, `is_idempotent_write_tool` and, when `read_only` is not true, to `mutating`.
3. **Run order.** (a) tool enabled in the session pack, else `TOOL_DISABLED`; (b) `precheck`: caps and preflight, no engine state, refusal is `SCRIPT_REJECTED` and asks nobody; (c) approval gate (rule 11), outside the session lock; (d) `Session::call`: sync the live canvas (after the wait, so the script sees the document as it is now), snapshot (every writing script, live or not), run, fold, one publish; (e) reply. A refusal at (a) to (c) is logged in the transcript like any failed call.
4. **Script form.** The body of an async function, so `await` and `return` work. Compile as the plugin does: try expression form `(async () => (SOURCE))` over the candidates from `expressionCandidates` (semicolon strips before comment strips, order ported verbatim), else statement form with the original source; `const a = 1; a + 1` returns `undefined`. The reply names the `mode`. Fresh `Runtime` and `Context` per call; nothing survives a run.
5. **Script API.** Globals are `studio` (frozen) and `console` (log, info, warn, error, debug; no timers, network, fs, `require`, `process`, `window`, `document`, module loader). `studio.call(tool, args)` runs an allowed typed tool and returns its parsed JSON reply or throws a `StudioError` (`code`, `message`, `path`, `next_step`, `detail`: the full envelope). Fast reads, which skip JSON and tool dispatch and see earlier writes of the same script (pending layout is settled first, as `Engine::call` does at `engine.rs:355-359`): `studio.node(id)` (the `list_nodes` summary shape, `engine.rs:1284-1294`, plus `text` for text nodes, or `null`), `studio.children(id)`, `studio.descendants(id, {kind?, name?, name_contains?, limit?})` (ids in paint order; above 200,000 ids without `limit` it throws, so no result is dropped silently), `studio.page()`; views are copies. Also `studio.args` and `studio.tools()` (callable names for this run).
6. **Dispatch and policy.** Inner calls go through `Engine::call`, never `Session::call`, so there is no canvas re-sync mid-script, no per-call patch, transcript or ledger entry. Session guards are re-applied by a per-run callable set: tool pack (`enabled_tools_config`, `disabled_tools`), then a classification table with default deny. Callable reads: every `readOnlyHint` tool except the image tools. Callable writes: `create_node`, `update_node`, `delete_node`, `apply_spec`, `apply_batch`, `lint_fix`, `add_comment`, `reply_comment`, `resolve_comment`, `set_dev_status`. Never callable: `exec_js`, `undo`, `redo`, `open_file`, `new_document`, `save_file`, `render_png`, `export_fig_file`, `import_web_capture`, `configure_session`, `set_in_progress`, `get_screenshot`, `get_design_context` (file paths, document switches, session side effects, images). A tool the pack disables throws `TOOL_DISABLED` and an unknown name `UNKNOWN_TOOL` (as a direct call would); a class-forbidden tool throws `SCRIPT_TOOL_NOT_ALLOWED`. A test fails when a registered tool is in no class, so a new tool needs a decision. `idempotency_key` inside an inner call is `INVALID_ARGUMENTS`. A panic in a host function is caught in the host and thrown as `INTERNAL_ERROR`, never unwound through the engine.
7. **Read-only.** With `read_only: true` only the read class is callable; any other tool throws `SCRIPT_READ_ONLY_VIOLATION` before it runs (stronger than the plugin's after-the-fact guard). A script that catches it still ends with `calls.refused` > 0. Tripwire: if a read tool changes `engine.revision` the run fails with `INTERNAL_ERROR` and `safe_to_retry` false (a Studio bug; there is no snapshot to restore). A read-only script takes no snapshot.
8. **One undo step, rollback.** Before the first call the Session snapshots (`EditSnapshot`). On a throw, limit, cancel, publish failure or panic, `roll_back` restores the document, undo depth, redo steps and revision, and nothing reaches the editor (`rolled back` is in the message; `safe_to_retry` follows state and is true). On success `History::fold_all_since(depth, label)` (new, `designos-doc`; folds every step above `depth`, whatever its origin, into one `Command::Batch`, sharing the body of `fold_since_range`; MCP steps are `Unspecified` and `fold_since` skips them, and marking each step after each call would only work if every tool pushed exactly one step, which no test pins) makes one MCP undo step. The label is `Agent: <run> (script)`; `engine.live_ops` accumulates every inner call (recording is forced on for the run) and the Session publishes one `LivePatch` with that label, so the editor applies one `Tx`: one undo step there too.
9. **Limits (constants, not inputs).** Wall clock `timeout_ms` from the end of the approval wait, counting host calls; JS heap 64 MiB; JS stack 1 MiB; the script thread has a 16 MiB stack so engine and tool recursion cannot overflow the process; console 200 lines of at most 2,048 characters, 64 KiB; `result` JSON at most 262,144 bytes. Output never fails a script: console and result are truncated with `console_truncated` / `result_truncated` and a preview. The interrupt handler checks the deadline and the client's cancel token, and once tripped returns true on every poll, so the run result is overridden by `SCRIPT_TIMEOUT` / `SCRIPT_CANCELLED` even if the script swallowed the exception. Memory and stack breaches are ordinary JS exceptions (`InternalError`, `RangeError`) that cannot exceed the cap. A promise that can never settle (no timers exist) is `SCRIPT_ERROR`. A single tool call is not interruptible, so the limit is as precise as the longest call (bounded by that tool's own caps).
10. **Preflight (lint).** Masked source (comments, strings, templates and regex blanked, ported from `maskExecJsLiterals`), then a native parse in a throwaway runtime (evaluating the async wrapper creates the function and runs nothing). Findings: errors `static-import`, `dynamic-import`, `syntax-error` (line and column) refuse; warnings go to the reply: `unavailable-global` (`window`, `document`, `fetch`, `setTimeout`, `process`, `require`: a local variable may share the name), `unbounded-loop` (`while(true)` / `for(;;)` with no `break`, `return` or `throw`), `tool-not-callable` (a literal `studio.call("…")` of a denied tool, or of a write tool when `read_only`). No `strict` or `--no-lint` input: a refused heuristic costs a round trip for nothing, and the native errors cannot be bypassed.
11. **Approval (follows the session mode; owner).** Skip or no Studio session: run. Ask and `read_only` not true: before running, the MCP gate writes `<approvals>/<id>.script.txt` (the script, at most 64 KiB, atomic) then `<id>.request.json` (`kind: "script"`, `tool_name`, first line as `input_summary` at most 200 characters, `script_bytes`, `script_lines`, `timestamp`), so #656's summary-only rule and `request_file_holds_only_a_summary` hold, and waits for `<id>.answer` (`allow`/`deny`/`withdrawn`) up to 300 s (the #656 constant, so the existing purge matches). The wait polls every 100 ms with `block_in_place` outside the session lock (other calls proceed) and stops on the cancel token; both files are removed whenever the wait ends. The gate lives in `DesignOSServer::call_tool`, the only transport entry; `Session::call` used as a library never asks. Deny, `withdrawn`, timeout or an unusable folder is `SCRIPT_NOT_APPROVED` (fail closed). Read-only scripts never write a request. Why a second gate and not only #656's path: that path carries a 200-character summary and Approve only on Claude; the MCP gate shows the whole script and answers for all four CLIs because Studio, not the CLI, owns this call. Mode: Studio sets `DESIGNOS_AGENT_PERMISSION_MODE` (`ask`/`skip`) by every path that already carries `DESIGNOS_SESSION_DIR`: the env block from `job.ask_mode`, the flag that already decides the hook (`terminal.rs:4549`), which the agy, Gemini and Grok configs copy; and for Codex the `env_vars` list of `codex_mcp_overrides!` plus an export next to `DESIGNOS_APPROVALS_DIR` (`terminal.rs:676`) from the tab's spawn-time mode (add `DESIGNOS_APPROVALS_DIR` to that list too). Tab: the MCP writes into `$DESIGNOS_APPROVALS_DIR` when set (Codex), else the root folder, shown on the active tab (`terminal.rs:3283`). Claude: the generated hook reads stdin first and, for a tool name ending `designos_exec_js`, prints `allow` and exits before the `waiting` status write (`agent_permissions.rs:118`) and the request; the separate #683 status handler of that hook group may still record `waiting`, so a read-only script can flash `Needs approval` until the tool's own next event (accepted; the card, not the label, asks). Every other tool is unchanged. The card reads `<id>.script.txt` once per request id and caches it, never per frame; `poll_approvals_in_dir` also removes the sibling when it purges a request, and the 7-day session sweep (`agent_session_files.rs`) covers an orphan from a dead MCP.
12. **Idempotency and the editor.** A write script with a key is stored and replayed by the existing ledger (same key and payload: the stored reply, `designos/idempotent_replay`, no re-run; stale once undone). `extract_live_and_gone` also reads `changed_node_ids`. The editor sees nothing until the script ends, then one patch; there is no streaming, because a throw must leave the editor untouched. The ID-remap note of `apply_batch` applies and is repeated in the description.
13. **Reply.** `{executed: true, mode, result, result_truncated, console: ["[log] …"], console_truncated, changed, created, changed_node_ids (at most 500 listed, from the recorded ops), changed_node_count, calls: {total, writes, refused, by_tool}, warnings: [{id, line, message, fix}], ms, read_only, undo_label}`. Result hints (`undefined`, `null`, `[]`, `{}`, ported from `resultWarning`) appear only when `changed` is false. A throw becomes `SCRIPT_ERROR` with `received` `{line, column, stack (2 KiB), console (last 20 lines), calls}`; when the throw came from `studio.call`, `failed_op` is the call index, `op` the tool and `cause` the typed error.
14. **Threat model.** The author is the agent, possibly steered by text in the file. The script adds no capability the typed tools lack (no fs, network, process, timers, other tabs; the tool pack and `owned_frames` still apply), adds speed and bulk, and bulk is one undo step. Residual risk: a memory-safety bug in vendored QuickJS reached by hostile script, with the user's privileges inside the MCP process. In Skip mode the agent already has a shell; in Ask mode this is the new exposure. Mitigations: pinned version, `cargo deny` advisories (#166), no module loader and no host objects beyond `studio`/`console`, fresh context per run, containment to one MCP process. Approval spoofing needs write access to the session folder (same boundary as #656).

## 8. Edge cases

- A script that writes nothing: `changed` false, no step, no patch, no snapshot kept; in Ask mode it still asked (it was not declared read-only).
- Throw after 30 writes: all rolled back, `calls.writes` is reported in the error's `received`.
- `try { studio.call(write) } catch {}` under `read_only`: continues; `calls.refused` shows it.
- A script that returns a huge value: preview and `result_truncated`, writes kept.
- A script that creates 20,000 nodes: the patch line may pass 16 MiB: `PATCH_TOO_LARGE`, rolled back, split the script.
- The user edits the file during the approval wait: the sync after the wait picks it up; during the run the designer's edits merge by id like any call.
- Client times out first (a shorter tool timeout than 300 s): the cancel token stops the wait or run and withdraws the request.
- Two requests queue per #656; the MCP serialises scripts on the session lock.
- MCP restart mid-script: nothing published; the agent reconnects and re-reads.
- The tab is closed while waiting: #656 writes `withdrawn` for requests in that tab's folder and the gate returns `SCRIPT_NOT_APPROVED`; a root-folder request (no tab id reached the MCP) is orphaned when the MCP exits with its CLI and the 300 s stale rule purges it.

## 9. Non-goals

Figma Plugin API compatibility (#258); a dry-run mode; screenshots and images in scripts; timers, network, fs, modules; `strict` lint; streaming progress; lazy approval at the first write (rejected: reads before the pause go stale and the timer must stop); a child process (hardening later); sharing a crate with #254 now; a per-script memory or time input; moving `fold_since`'s agent-turn folding.

## 11. Performance budgets

Targets, ASSUMPTION until measured on the 112,474-node VSF file's scoped copy and recorded in the PR: engine start plus prelude 2 ms or less (probe: 56 microseconds for the context); `studio.call` overhead 100 microseconds or less outside the tool's own work; `studio.node` 10 microseconds or less; a read-only walk of 100,000 nodes in 3 s or less under the 64 MiB cap; one snapshot clone of the scoped copy 150 ms or less per writing script (the `EditSnapshot` the Session already takes for a live write, now also taken when no editor is attached; none for read-only; N per-call clones become one).
