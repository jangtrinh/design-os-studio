## 1. Summary and user story

As a designer using Studio, every button, field, menu, row, toggle and dialog looks and behaves like one Untitled UI dark component in each of its states, so the app reads as one system and focus is always visible. As an implementer of specs D–K, I call one kit function per widget kind with a size and a state and get the Untitled look; I never pick a colour, radius or font in a surface file.

**S3 State model.** Six table states, Default, Hover, Pressed, Focused, Disabled and Selected, plus **Loading** for buttons. Precedence: Disabled > Loading > Pressed > Selected > Hover > Default. Focused is additive: the ring is drawn on top of whichever look applies.
- Hover follows the pointer only.
- Pressed (pointer down) is derived because the kit has none: brand fills go to Orange-600, destructive to Red-800 `#991B1B`, neutral fills to `bg-quaternary` `#404040` (contract `BG_PRESSED`; only `text-primary`/`text-secondary` text and icons at `fg-quaternary_hover` or brighter sit on it).
- Loading (kit, buttons only): the Hover look, a 16 px spinner (`Loading/Inline` arc) before the label, no pointer response. No Studio surface starts an async button today, so the tables carry no Loading column; a surface spec that needs one uses this rule.
- Selected + Hover keeps the Selected fill and takes the hover text and icon colour.
- Focus traversal: `widgets/field_tab.rs` stays as shipped. While a field holds focus, Tab and Shift+Tab walk fields only; when no field holds focus, egui's Tab walk reaches buttons, tabs, toggles, checkboxes, swatches and rows, and each draws the S4 ring while it holds focus. Text fields show their focused border whenever they hold focus, pointer or keyboard (kit Input Focused).

**S4 Focus ring (FACT, section 2).** A 2 px `focus-ring` `#F97316` band from 2 px to 4 px outside the control, outer radius = control radius + 4, with the 2 px gap left showing the surface. Text fields and selects draw no ring: their border becomes 2 px `border-brand` `#FB923C`. Swatches ring in their own colour (kit); Studio marks the selected swatch with a 2 px `focus-ring` outline (derived).

**S5 Disabled.** The Default look at 50 % opacity (alpha x 0.5 on fill, border, text and icon); fields dim the box only, never the label. Not focusable, no hover, no pressed. `TEXT_DISABLED` (`theme.rs:53`) retires.

**S6 Surface-relative fills.** Tables 3.4 are written for a `bg-primary` surface: hover `bg-primary_hover` `#171717`, selected `bg-secondary_hover` `#262626` (R8.2; segmented tabs included, so a selected tile differs from its `#171717` container), pressed `bg-quaternary` `#404040`. On a `bg-secondary` surface (fields, cards) hover moves up to `bg-secondary_hover`, selected and pressed to `bg-quaternary`. On `bg-quaternary`, text becomes `text-secondary` `#D4D4D4` (6.99:1) and icons `fg-quaternary_hover` `#A3A3A3` (4.11:1), because the contract forbids `text-tertiary` and `fg-quaternary` there. Which surface each panel uses is spec A's.

**S7 Icons (R6).** The icon set stays; colour by role: default `fg-quaternary` `#737373` (4.18:1 on `#0A0A0A`, 3.19:1 on the selected `#262626`; non-text minimum 3.0), hover and pressed `fg-quaternary_hover` `#A3A3A3`, selected `fg-secondary_hover` `#E5E5E5`, brand marks `fg-brand-primary`. Toolbar tools default to `fg-quaternary_hover` (derived: 20 px tool glyphs are the toolbar's only content). Unchecked checkbox borders and radio rings keep the kit's 1 px `border-primary` `#404040` (contract `BORDER_STRONG`; 1.91:1 on `bg-primary`, 1.73:1 on `bg-secondary`), a named exception to the 3:1 boundary rule decided by the owner (R10.7). Text fields keep the same kit border (controller default, R2). Component layers keep canvas cyan `#06B6D4` (plan.md canvas exception).

## 4. Data model / schema changes

None to the document, its files or the MCP schema. Chrome only. In memory, the kit adds three small value types (all **new names**): `kit::Size { Xs, Sm, Md }`, `kit::State { Default, Hover, Pressed, Focused, Disabled, Selected, Loading }` and `kit::Look { fill, border, border_w, text, icon, mark }` (five `Color32` plus a width; `icon` is the control part of a compound widget and `mark` its inner mark, as each table's Parts line says: radio circle and dot, toggle track and knob, slider handle fill and border, progress track and fill), resolved by one pure function per widget kind. No persisted settings.

## 8. Edge cases

- **Concentric radius.** Settled by R5 and R8.5: menu items are radius 8 at inset 8 inside a 16 menu (16 − 8 = 8), segment tiles 6 inside an 8 control with a 2 inset. The kit's own 6-in-8 pills are not used.
- **Focus ring clipping.** The ring sits 2–4 px outside the control. Inside a scrolled or clipped panel it is drawn with the parent clip widened by 4 px; at a panel edge it is clipped, never shifted.
- **Pixel snapping.** At 1x a 2 px ring is two device pixels; at 1.5x and 2.25x (Fold 7) the ring rect is snapped to physical pixels like `snap_y` (`widgets/mod.rs:136`).
- **Focus versus pointer.** The ring shows for keyboard focus (Tab when no field holds focus, S3; arrow keys where a widget has them). A text field shows its focused border whenever it has focus, including after a click, because that is the kit's Input Focused state.
- **Disabled + focused** cannot happen: a disabled control is not focusable. **Selected + hover** uses the Selected look with the hover text colour.
- **Mixed values** ("Mixed" in number fields) use `text-placeholder` like a placeholder.
- **Destructive** buttons use the error ramp (`bg-error-solid`), never the brand.
- **Canvas exceptions**: component cyan, selection blue, guide red and Dev emerald stay as in plan.md; a component layer's row icon and label in Layers keep `canvas-component #06B6D4`.
- **Light canvas labels** (`TEXT_ON_LIGHT_CANVAS*`) are canvas overlays, not widgets; unchanged.
- **Hover on a filled surface.** A widget on `bg-secondary` uses the `_hover` of that surface (`bg-secondary_hover #262626`), never `bg-primary_hover #171717`, which would be invisible there (rule S6).
