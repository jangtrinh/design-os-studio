## 1. Summary and user story

As a designer using Studio, every button, field, menu, row, toggle and dialog looks and behaves like one Untitled UI dark component in each of its states, so the app reads as one system and focus is always visible. As an implementer of specs D–K, I call one kit function per widget kind with a size and a state and get the Untitled look; I never pick a colour, radius or font in a surface file.

## 3. Behaviour rules

### 3.1 Rules every widget follows

**S1 Brand remap (R4).** The kit's Brand ramp is replaced by Studio orange and the Untitled Orange ramp. Names stay Untitled; spec A owns the token store and wins on any conflict.

**S2 Size steps (R5).**

Editor fields at 32 are derived: the kit's smallest `Input field` is sm 36. Panel titles are text-sm 14/20 semibold; modal titles text-md 16/24 semibold (kit `_Modal header`).

**S3 State model.** Six states: Default, Hover, Pressed, Focused, Disabled, Selected. Precedence: Disabled > Pressed > Selected > Hover > Default. Focused is additive: the ring is drawn on top of whichever look applies. Hover follows the pointer only. Focused follows keyboard focus (Tab, arrows), except text fields, which show the focused border whenever they hold focus (kit Input Focused). Pressed (pointer down) is derived because the kit has none: brand fills go to Orange-600, neutral fills to `bg-quaternary` `#404040` (token-contract `BG_PRESSED`; only text-primary, text-secondary and non-text icons sit on it). Selected + Hover keeps the Selected fill and takes the hover text and icon colour.

**S4 Focus ring.** 2 px `focus-ring` `#F97316` band from 2 px to 4 px outside the control (geometry: section 2, gap order INFERENCE), radius = control radius + 4, the 2 px gap left unpainted (it shows the surface, as the kit's surface-coloured inner shadow does). Text fields and selects draw no ring: their border becomes 2 px `border-brand` `#FB923C`. Swatches ring in their own colour (kit), and Studio adds `focus-ring` for the selected swatch (derived).

**S5 Disabled.** The Default look at 50 % opacity (alpha x 0.5 on fill, border, text and icon); fields dim the box only, never the label. Not focusable, no hover, no pressed. `TEXT_DISABLED` (`theme.rs:53`) retires.

**S6 Surface-relative hover.** Kit hover and selected fills are defined on `bg-primary`. On a `bg-primary` surface Studio uses hover `bg-primary_hover` `#171717`, selected `bg-secondary_hover` `#262626` (token-contract `BG_SELECTED`, owner question OQ-2 there; the kit literal is `bg-secondary`) and pressed `bg-quaternary` `#404040`. On a `bg-secondary` surface (fields, cards) hover moves one step up to `bg-secondary_hover`, or it would vanish; selected and pressed use `bg-quaternary`. Which surface each panel uses is spec A's; tables 3.4 are written for `bg-primary`.

**S7 Icons (R6).** The icon set stays; colour by role: default `fg-quaternary` `#737373` (4.18:1 on `#0A0A0A`, non-text minimum 3.0), hover and pressed `fg-quaternary_hover` `#A3A3A3`, selected `fg-secondary_hover` `#E5E5E5`, brand marks `fg-brand-primary`. Toolbar tools default to `fg-quaternary_hover` (derived: 20 px tool glyphs are the toolbar's only content). Component layers keep canvas cyan `#06B6D4` (plan.md canvas exception).

### 5.2 API sketch (all **new names**; the worker may rename inside `kit/` but not change the shape)

```rust
pub enum Size { Xs, Sm, Md }                 // Xs editor (R5), Sm Home/dialog body, Md dialog footer actions
pub enum State { Default, Hover, Pressed, Focused, Disabled, Selected }
pub struct Look { pub fill: Color32, pub border: Color32, pub border_w: f32, pub text: Color32, pub icon: Color32 }
pub fn state_of(r: &egui::Response, selected: bool, enabled: bool) -> State;  // precedence S3

pub fn button(ui: &mut Ui, rect: Rect, key: impl Key, label: &str, h: Hierarchy, size: Size, enabled: bool) -> Response;
pub fn focus_ring(p: &Painter, rect: Rect, radius: f32);
```

Every `*_look` function is pure and is what the tests in section 10 pin. Paint functions only read a `Look`.

## 8. Edge cases

- **Concentric radius.** The kit puts a `radius-sm` 6 item pill 6 px inside a `radius-md` 8 menu, which breaks today's law P4 (inner = outer − inset = 2). Spec B rewrites P4; until it lands the kit follows the Untitled values and the ratchet's non-concentric counter is allowed to rise only in `kit/` (FACT: kit values; INFERENCE: spec B keeps them).
- **Focus ring clipping.** The ring sits 2–4 px outside the control. Inside a scrolled or clipped panel it is drawn with the parent clip widened by 4 px; at a panel edge it is clipped, never shifted.
- **Pixel snapping.** At 1x a 2 px ring is two device pixels; at 1.5x and 2.25x (Fold 7) the ring rect is snapped to physical pixels like `snap_y` (`widgets/mod.rs:134`).
- **Focus versus pointer.** The ring shows for keyboard focus (Tab, arrow keys). A text field shows its focused border whenever it has focus, including after a click, because that is the kit's Input Focused state.
- **Disabled + focused** cannot happen: a disabled control is not focusable. **Selected + hover** uses the Selected look with the hover text colour.
- **Mixed values** ("Mixed" in number fields) use `text-placeholder` like a placeholder.
- **Destructive** buttons use the error ramp (`bg-error-solid`), never the brand.
- **Canvas exceptions**: component cyan, selection blue, guide red and Dev emerald stay as in plan.md; a component layer's row icon and label in Layers keep `canvas-component #06B6D4`.
- **Light canvas labels** (`TEXT_ON_LIGHT_CANVAS*`) are canvas overlays, not widgets; unchanged.
- **Hover on a filled surface.** A widget on `bg-secondary` uses the `_hover` of that surface (`bg-secondary_hover #262626`), never `bg-primary_hover #171717`, which would be invisible there (rule S6).

## Open questions for the owner

Each has a recommended answer first, and the spec is written to it, so a "yes" needs no rework. Question 3 shares its answer with token-contract OQ-1, and 5 with OQ-2.

1. **Editor fields: 32 px tall (xs) or the kit's smallest 36 (sm)?** Recommended: **32**. R5 sets row and button xs 32; a 36 field in a 32 row grid would push every Inspector row down. The kit has no xs field, so 32 is marked derived.
2. **Button and tab labels in the editor: text-sm 14 (kit, every size) or text-xs 12 (R5 "rows and labels")?** Recommended: **text-sm 14 semibold**, as the kit does at xs, sm and md; text-xs stays for rows, fields and menu items. Reverse it and only S2's first row changes.
3. **Placeholder text: the kit's `#737373` is 4.18:1 on `#0A0A0A` and 3.78:1 on `#171717`, below AA 4.5. Lift it?** Recommended: **yes, `text-placeholder` = `#A3A3A3` (7.85:1)**, as token-contract OQ-1 recommends; the tables use that value. Answering it once settles both specs.
4. **Destructive hover: the kit puts white on `#EF4444` (3.76:1), below AA. Keep the kit or darken?** Recommended: **keep the kit hover `bg-error-solid_hover`** (it shows for under a second under the pointer, and the default `#DC2626` is 4.83:1), and record it as a known kit exception. Alternative: hover = `bg-error-solid` with no change.
5. **Selected rows: fill `bg-secondary_hover` `#262626` (token-contract OQ-2 recommendation) or the kit literal `bg-secondary` `#171717`; text stays the kit's `text-tertiary`?** Recommended: **`bg-secondary_hover` with `text-tertiary` (6.0:1)**: `#171717` equals the hover fill, so a selected row would look hovered; the kit text keeps the canvas selection the brightest mark.
