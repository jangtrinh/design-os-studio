DESIGN:OS Studio compared with OpenPencil, Penpot, Lunacy and Figma MCP

DESIGN:OS Studio is a high-quality, FREE Figma alternative built for AI, released as FREE + source-available (PolyForm Shield). It is a native Rust editor that opens and writes .fig files with no Figma app, and lets coding agents edit a .fig headless through designos-mcp (39 tools, v0.7.14) or the designos CLI. design:os is not affiliated with or endorsed by Figma. Saving a .fig has known issue #834, which is still open (P1): a numbered list loses its numbers and the spacing between items grows; a breadcrumb arrow icon renders heavier (the issue title is ".fig save drops numbered-list formatting and changes icon strokes"); and the writer turns inherited or variable-bound paints on instances into literal overrides, so a fill bound to a variable becomes a fixed hex.

This page is a factual comparison for people searching for a free Figma alternative, a desktop .fig editor, or a Figma MCP alternative. "Figma MCP alternative" usually means a server that talks to the Figma API or a Figma plugin. designos-mcp is different: it edits a .fig file on disk, with no Figma app and no Figma token. Both can be useful; they are not the same job.

The facts below were checked against each product's public pages on 13 November 2026 (Asia/Saigon). Where a figure is not published, this page says so. Sources are listed at the end.

Who each tool is for

DESIGN:OS Studio is for people who want a local desktop editor, and a headless agent path, that opens and writes a .fig on disk with no Figma app and no Figma account. Jang Trịnh, a creative technologist and autonomous system architect, started design:os on 10/10/2026. The current release is v0.7.14.

OpenPencil is for people who want a local-first editor under the MIT License, with a large MCP and CLI surface, peer-to-peer collaboration, and official claims that it reads and writes .fig. It also runs in the browser. A hosted Cloud product is on a waitlist; no public Cloud price was published when this page was written.

Penpot is for teams that want a mature, self-hostable design platform in the browser, under the Mozilla Public License 2.0, with real-time collaboration and an official MCP server that reads and writes the open Penpot file. It does not open a native .fig. Migration from Figma goes through the Penpot Exporter plugin.

Lunacy (by Icons8) is for people who want a free native desktop editor with a built-in Icons8 asset library, native .sketch read and write, and optional cloud collaboration. It opens and imports .fig. Its native format is .free. Saving back to .fig is not documented on the official export list.

Figma's official MCP server is for people whose files already live in Figma and who want the official agent integration into those files. It is not a desktop .fig editor. It does not operate on a .fig sitting on your disk.

DESIGN:OS Studio and OpenPencil

OpenPencil is stronger where a MIT-licensed local editor, a large published MCP and CLI surface, and peer-to-peer collaboration matter. Its homepage and download page present a free desktop app for macOS, Windows and Linux, a web app with no install, 24 CLI commands that work on a file with no app running, and an MCP server over stdio or HTTP. It states that it reads and writes .fig, and that you can export to .fig, PDF, PPTX, SVG, HTML and JSX. Collaboration in a shared room does not need an account. Those are real advantages.

Studio differs in licence, stack and freshness. It is a native Rust and GPU editor (wgpu, with a tiny-skia CPU path for headless captures), released as FREE + source-available under PolyForm Shield 1.0.0. That licence lets you use and modify it, including for paid work, and does not let you resell it or build a competing product. It ships designos-mcp with 39 tools in v0.7.14, pinned by the tool table in the README, and a designos CLI that can inspect, scan a design system, generate code and write a .fig with no window. It does not offer live multiplayer. It is also newer: work on design:os started on 10/10/2026.

On MCP tool counts, this page repeats OpenPencil's own homepage figure of 126, and also records what the MCP docs say: "100+" shared design tools, plus MCP-only operations, with 115 named tools counted in the published tables on 13 November 2026. If you need a single audited number, read their live docs. Studio's 39 is the count in the v0.7.14 README tool table, which is generated from designos-mcp.

If you want MIT terms, a large agent tool list, P2P collab, or a web app, OpenPencil is the stronger fit. If you want a native Rust desktop studio, a 39-tool local MCP and CLI with no Figma app, and PolyForm Shield terms, look at Studio, and read #834 before you rely on .fig save.

DESIGN:OS Studio and Penpot

Penpot is stronger on maturity, self-hosting and team collaboration. You can run it in Penpot's cloud or on your own servers. Cloud Professional is $0 per user per month. Self-host Professional is free, with unlimited users, teams and files on your infrastructure. The product is licensed under MPL-2.0, and the source is public. Inspect is available without a separate paid Dev Mode add-on. The official MCP server, remote or local, lets an agent read and modify the focused Penpot page, and Penpot describes this MCP as free with no credit caps. For a team that wants a design platform it can host and govern, Penpot is the stronger choice.

Studio differs on the file and on where the agent works. Penpot does not open a native .fig. Official migration uses the Penpot Exporter plugin inside Figma, then import into Penpot; the enterprise migration guide says to expect some layout cleanup, and that the exporter is for one-off migration, not continuous sync. Studio opens and writes the .fig on your disk, with #834. designos-mcp talks to that file, with no Penpot (or Figma) session. Studio has no real-time multiplayer and no self-hosted team workspace. It is a local desktop app, not a browser platform.

If you need browser collaboration, self-hosting, or MPL-2.0 terms, choose Penpot. If you need to keep a .fig on disk and let an agent edit it headless, choose Studio or OpenPencil, not Penpot.

DESIGN:OS Studio and Lunacy

Lunacy is stronger as a free native desktop design app with a built-in Icons8 library of icons, illustrations and photos, native .sketch open, edit and save, optional real-time cloud collaboration, and a low hardware bar. It runs on Windows, macOS and Linux. The About page says it is completely free for personal and commercial use. You can work offline on local documents. A built-in MCP server sits next to the app, and the 11.6 release notes say an LLM can edit the selection over MCP. For a designer who wants a familiar desktop editor and a large offline-capable asset library, Lunacy is the stronger fit.

Studio differs on .fig writing and on headless agents. Lunacy opens and imports .fig, as of the v12 release notes (9 February 2026), which replaced Figma API import with .fig file import. Its native format is .free. Official export formats are raster and vector image types, not .fig. This page does not claim that Lunacy writes .fig, because that is not published. (An older features page still lists ".fig format support" under features unlikely to appear. That conflicts with the later About, Interface and v12 notes. This page follows the more specific, later docs and treats .fig write-back as not published.) Studio writes .fig, with #834. designos-mcp and the designos CLI can edit a .fig with no window; Lunacy's MCP is documented as a local server alongside the running app, and a tool count is not published.

Paid Lunacy plans unlock higher-resolution graphics without Icons8 attribution, AI tools, and more cloud and team capacity. Exact current Pro pricing should be read on the live pricing page, because the Help article and the marketing page use different plan names.

DESIGN:OS Studio and Figma MCP

Figma's official MCP server is stronger wherever your source of truth is already a Figma file: official integration, a remote server that needs no desktop app, write to the canvas on paid plans, Code Connect, skills, and a published tools list that covers design-to-code, code-to-design, libraries and (separately) Figma Weave. If your team designs in Figma and you want an agent to read or write those files, the official server is the direct path. This page does not treat it as a weaker product. It is a different job.

Studio differs because designos-mcp does not talk to the Figma API and does not need a Figma token, a Figma seat, or the Figma app. It opens a .fig on disk. That is useful when you have a file and no Figma session, or when an agent should run headless in CI. It is not a replacement for Figma, and it is not a drop-in stand-in for Figma MCP. Other community MCP servers that talk to Figma also exist; this page compares only the official Figma MCP server.

Access and cost follow your Figma plan. The remote server is available on all plans, with rate limits. Writing to the canvas is on Professional, Education, Organization and Enterprise, and writing outside drafts needs a Full seat. A Dev seat can write in drafts and has read access to other files. The desktop server needs a Dev or Full seat on a paid plan (or Education or Government, as documented) and does not support writing to the canvas. The feature is free during beta and will become usage-based.

On tool counts: Figma's official tools page does not publish a single total. On 13 November 2026 the published index listed 19 read tools and 15 write tools, with many write tools marked remote-only, and a separate Weave group that needs a paid Weave account. Studio publishes 39 tools for v0.7.14.

Which should you pick

  • Choose DESIGN:OS Studio if you want a native desktop editor that opens and writes a .fig on your disk, and a local MCP server plus CLI so a coding agent can inspect, edit and export that file with no Figma app and no Figma token. Read #834 first. Use it FREE under PolyForm Shield 1.0.0.
  • Choose OpenPencil if you want MIT terms, a free local (and web) editor that also claims .fig read and write, a large MCP and CLI surface, or peer-to-peer collaboration without an account.
  • Choose Penpot if you want a mature browser design platform you can self-host, real-time team collaboration, MPL-2.0 terms, and an official MCP server against Penpot files. Plan a migration through the Penpot Exporter; do not expect to open a raw .fig.
  • Choose Lunacy if you want a free native desktop editor with a built-in Icons8 asset library, native .sketch, optional cloud collab, and offline local files. Use it to open a .fig; do not assume it will write one back, unless Icons8 later documents that.
  • Choose Figma's official MCP server if your designs live in Figma and you want the official agent path into those files, including write to the canvas on a qualifying plan and seat.

You can also use more than one. A team can keep Figma (and Figma MCP) as the shared cloud canvas, and use Studio or OpenPencil on a .fig export when an agent needs to work on a file on disk. That is a neighbouring workflow, not a swap of one product for the other.

Known limitations of DESIGN:OS Studio

  • Issue #834 is still open (P1) as of 13 November 2026. The title is ".fig save drops numbered-list formatting and changes icon strokes". The issue body, measured on the Untitled UI PRO v8.0 kit, says: a numbered list loses its numbers and item spacing grows; a breadcrumb arrow icon renders heavier (in v0.5.0 it also shifted into the next word); and the writer turns inherited paints into literal instance overrides, including a fill bound to a variable (example: bg-secondary became the literal #FAFAFA). A literal value cannot follow a variable mode. The README recommends keeping the original .fig, or saving as .designos, until this is fixed. Pixel-mismatch counts in the issue were measured on v0.5.0 and v0.6.0 and are not restated here as current.
  • No hosted collaboration. Studio has no real-time multiplayer, no enterprise cloud administration with SSO and SCIM, and no hosted comment notifications. The README is explicit: if you need those, use Figma (optionally with the live design-os-figma-plugin bridge) or a hosted Penpot instance.
  • Windows and Linux packages are built by the same release workflow but are not verified before release. macOS packages are verified on Apple Silicon.
  • The product is young. Work on design:os started on 10/10/2026. Penpot, Lunacy and Figma have longer public histories. That is a fair reason to trial before you depend on it for a large production kit.
  • Other published limits in v0.7.13 (see the changelog): re-solving the imported Untitled UI PRO v8.0 kit still moves 2,039 layers, about 1 percent; a nested instance can lose overrides when its variant is switched by hand; a main-component sync with no change can resize instances imported from a .fig; after a .fig save and reopen, a change made inside a nested instance can be lost at the next edit of the main component (#1925).

FAQ

Is DESIGN:OS Studio free?

Yes. DESIGN:OS Studio is a high-quality, FREE Figma alternative built for AI, released as FREE + source-available (PolyForm Shield). You can use and modify it freely, including for paid work. The terms are PolyForm Shield 1.0.0. You cannot resell it or use it to build a product that competes with it. Pre-built packages for v0.7.14 are on the GitHub Releases page.

Is design:os affiliated with Figma?

No. design:os is not affiliated with, endorsed by, or sponsored by Figma, Inc. "Figma alternative" in the product sentence and in this comparison describes a category of tool. It is not a claim of parity, partnership, or official compatibility beyond what the Studio README and issue #834 actually say about reading and writing .fig files.

Can DESIGN:OS Studio open and save .fig files?

Yes, with known issue #834, which is still open (P1). Studio reads .fig containers and writes version 106 with meta.json and images/. On save, a numbered list loses its numbers and item spacing grows; a breadcrumb arrow icon renders heavier; and inherited or variable-bound paints on instances are written as fixed values. Keep the original .fig, or save as .designos, until #834 is fixed. Details are in the issue and in the Studio README.

Is designos-mcp a Figma MCP alternative?

It can show up in the same search, but it is a different job. Figma's official MCP server talks to a Figma file in Figma. It needs a Figma account, and write access depends on plan and seat. designos-mcp is a local stdio server, 39 tools in v0.7.14, that inspects, edits and exports a .fig on disk, with no Figma app and no Figma token. Both can be useful. If your files live in Figma, use Figma MCP. If you have a .fig on disk and no Figma session, use designos-mcp or the designos CLI.

What platforms does DESIGN:OS Studio run on?

v0.7.14 ships packages for macOS (a universal .dmg, verified on Apple Silicon), Windows (a .zip with a per-user install script) and Linux (.deb and .tar.gz). The Windows and Linux packages are built by the same release workflow but are not verified before release. You can also build from source. There is no account and no telemetry.
